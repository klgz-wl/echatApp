# Android 归因实施与校验规范

文档包版本：1.0.0｜整理日期：2026-11-03｜适用结构：`app`、独立 `core`、`integration/analytics-appsflyer`。

本目录是可独立发送的完整规范。实施、校验、排障和执行提示词均在本文；配套文件只有[实施与验收记录模板](实施与验收记录模板.md)、[文档包检查工具](检查文档包.py)和[版本清单](版本清单.json)。接收方无需访问来源工程、其他项目文档或原开发电脑。

本文规定沿用既定架构的 Android 项目如何实现同一套归因行为，不提供任意架构的适配方案。项目根目录、源码命名空间、安装包名、SDK 身份、网络环境、证书及存储名称全部读取目标项目自身配置。不得复制其他项目的服务身份。

规范覆盖已经实现的客户端行为及需要完成的外部契约，**不代表接收项目已通过测试，也不代表服务端幂等、平台投放归因或后台实收已经验收**。每个项目填写自己的实施记录和证据。

## 1. 使用及交付约定

1. 发送整个“归因”目录或其 ZIP，不单独发送主文档。目录可以放到接收电脑的任意位置；所有附件链接都相对此目录解析。
2. 接入项目建议存放于 `docs/公共规范/归因/`，该位置是仓库内部约定，不是开发机绝对路径。命令中的“仓库根目录”指接收项目自己的 Gradle 根目录。
3. 源码定位使用“模块＋包内目录＋类名”。`<APP_PACKAGE_PATH>`／`<CORE_PACKAGE_PATH>` 是将目标 namespace 的点替换为斜线后得到的目录，不是实际文件名。先按类名搜索，不能把占位符直接当作存在的路径。
4. 在[记录模板](实施与验收记录模板.md)的副本填写目标配置、差异、测试结果和待办；项目记录存放在该公共规范目录之外。公共包不存账号、密钥、原始标识、证书或真实归因响应。
5. 主文档和附件作为一个版本维护。修改后提升版本并重新生成文件摘要；接收方先运行检查工具，检查通过只证明文档包完整、链接可用，不证明 Android 实现正确。

在文档包目录执行（需要 Python 3.9+，仅用标准库）：

```bash
python3 检查文档包.py
python3 检查文档包.py --zip ../android-attribution-spec-1.0.0.zip
```

工具依据自身文件定位文档包，不依据终端当前目录或任何工程路径；ZIP 输出位置由执行者指定。已存在的输出文件不会被覆盖。

## 2. 架构与定位方式

沿用 Kotlin、Compose、MVVM、Clean Architecture、Hilt、Coroutines／Flow、Retrofit／OkHttp。Core 不引用 app 的 `BuildConfig`；app 将外置配置转换为类型化配置并注入。第三方 API 封装在 integration，页面不直接调用 SDK、Repository 或归因 HTTP。

| 模块与约定位置（均相对目标仓库根） | 职责及核对类名 |
| --- | --- |
| `config/app.properties`、`config/dev.properties`、`config/prod.properties` | 公共策略、各环境 SDK 身份和开关；秘密使用忽略的本地配置或环境变量 |
| `app/build.gradle.kts` | `flavorApplicationIds`、`flavorEndpoints`；校验配置，生成 BuildConfig／资源／Manifest 占位符 |
| `gradle/libs.versions.toml` | 依赖版本及别名，核对最终解析版本而非只看声明 |
| `app/src/main/java/<APP_PACKAGE_PATH>/di/` | `ConfigurationModule`，注入 `ClientIdentity`、`CoreRuntimeConfig`、归因及 SDK 配置 |
| app 的 `MainActivity`、`ui/login/` | `AuthViewModel`、`SplashScreen`；真实认证、地区门禁、首页首帧信号；绑定当前前台 Activity |
| app 的 `analytics/` | `AnalyticsHub`、`ForegroundAnalytics`、`AttributionCallbackReporter`；正常统计与归因专用行为分开控制 |
| `core/src/main/java/<CORE_PACKAGE_PATH>/attribution/` | `AttributionCoordinator`、`AttributionModels`、`AttributionLedger`、`AttributionReports`、`HomeAttributionGate`、`AttributionPrivacy` |
| core 的 `auth/`、`device/` | `SessionCoordinator`、`PreferenceSessionStorage`、`AuthRepository`、`AnonymousStartup`、`PersistentDeviceIdentity`、`AdvertisingIdProvider` |
| core 的 `network/`、`analytics/` | 真实 API、序列化、请求所属身份及日志脱敏；`BackendAnalyticsSink` 的有界事件队列 |
| `integration/analytics-appsflyer/src/main/java/<CORE_PACKAGE_PATH>/integration/appsflyer/` | `AppsFlyerAnalytics`、`AppsFlyerConfig`、`ForegroundAttributionStart`、`AttributionRequestGate`、`AttributionCallbackState`、`GcdConversionClient`、`GcdAttributionRefresh`、`HomeGcdAttributionVerification`、`GoogleInstallReferrerReader`、`InstallReferrerEvidenceCache`、`InstallReferrerAttribution` |
| 各模块 `src/test/java/` | 对应状态机、时序、存储故障、请求序列化、身份隔离测试 |
| `app/src/main/AndroidManifest.xml`、`app/src/main/res/xml/data_extraction_rules.xml`、`app/proguard-rules.pro` | 自动初始化、备份／设备迁移、AD_ID 权限、release 混淆与收缩规则 |

类名用于明确职责边界；缺少时按该结构新增。不能用“找不到来源工程”作为阻塞，本文已经提供行为、字段与验收要求；目标项目缺少真实接口或平台配置时，记录具体缺口，不伪造实现。

## 3. 配置清单

只有 `environment` 维度的 `dev`／`prod` 两个 flavor；debug／release 为独立构建类型，页面 A／B 模式不与 flavor 绑定。以下策略值为本规范基线，变更需记录原因并重新验证时序；服务身份必须用目标项目配置。

| 配置项 | 基线／来源 | 约束 |
| --- | --- | --- |
| app／core namespace | 目标 `config/app.properties` | 两者独立，不能从安装包名推断源码路径 |
| applicationId、versionName | 当前实际构建 | 所有上报使用实际 flavor 包名与版本，不使用 namespace 或文档示例 |
| API／WebSocket／CDN | 目标 `flavorEndpoints` | 保持目标环境，不迁入其他应用地址 |
| `APPSFLYER_GCD_BASE_URL` | 对应 flavor endpoint；基线 `https://gcdsdk.appsflyer.com/` | 独立 HTTPS 根地址，不能拼业务 API 前缀 |
| AppsFlyer Dev Key／启用开关 | 目标各环境配置 | 和当前 applicationId 在平台中的应用匹配，不打印密钥 |
| Firebase／Google 登录配置 | 目标 flavor JSON 与既有认证配置 | 核对实际包名、证书与资源；没有 Google 登录需求不新增入口 |
| 数数 App ID、地址、模式 | 目标环境配置 | 与 `ENABLE_THINKINGDATA` 独立管理 |
| `ENABLE_BACKEND_ANALYTICS` | 目标配置，基线 true | 与数数开关独立；仅控制自有事件，不等同补报成功状态 |
| `ATTRIBUTION_TIMEOUT_MS` | 3000 | 主动认证前归因等待上限 |
| `ATTRIBUTION_LOGIN_TIMEOUT_MS` | 8000 | 真实认证完成后的归因等待上限 |
| `ATTRIBUTION_HOME_TIMEOUT_MS` | 10000，保留兼容 | 正式首页不再使用此项叠加 SDK 等待 |
| `ATTRIBUTION_HOME_DATA_DELAY_MS` | 1000 | 补报业务成功时刻起的共享最短间隔，成功落盘后才可放行 |
| `ATTRIBUTION_RETRY_ATTEMPTS` | 10 | 单目标每轮补报／补报后 profile 刷新的最多尝试数，含首次 |
| `ATTRIBUTION_RETRY_INTERVAL_MS` | 1000 | 全局检查／有限重试间隔；检查不等于实际 SDK 网络请求 |
| `ATTRIBUTION_CACHE_WAIT_MS` | 200 | 恢复缓存相关等待，不是对慢读盘采取清空覆盖的许可 |
| `ATTRIBUTION_STORAGE_TIMEOUT_MS` | 3000 | 账本存储操作上限；超时保留待处理状态 |
| `APPSFLYER_MIN_SESSION_INTERVAL_SECONDS` | 1 | SDK 最短会话间隔，仍遵守 SDK 节流及前台在途保护 |
| `APPSFLYER_REQUEST_TIMEOUT_MILLIS` | 15000 | 本地在途 lease 上限，不是强制刷新平台数据的承诺 |
| `APPSFLYER_GCD_REQUEST_TIMEOUT_MS` | 10000 | 前置及首页各次 GCD 的单次请求上限 |
| `INSTALL_REFERRER_REQUEST_TIMEOUT_MS` | 10000 | 单次辅助读取上限，所有退出分支释放连接 |
| `INSTALL_REFERRER_PAID_MEDIUMS` | `cpc,ppc,paid,paid_social,paid_search,display,cpm` | 本方案外置投放规则；目标项目核实自己的已确认 medium，不是平台保证 |
| `STORAGE_NAME`、`INSTALL_REFERRER_STORAGE_NAME` | 目标项目自身配置 | 非空、环境一致；已有安装更名需迁移，不能静默丢成功凭据 |
| `ADVERTISING_ID_TIMEOUT_MS` | 1000 | 每个调用方等待当前系统 GAID 的上限 |
| `ANALYTICS_QUEUE_CAPACITY` | 256 | SDK 回调自有事件的有界内存队列容量 |
| `APPSFLYER_DEBUG_LOGGING` | 所有变体 false，运行时也强制关闭 | SDK 完整调试输出可能包含 GAID |
| `APPSFLYER_DIAGNOSTIC_LOGGING` | 目标诊断策略 | 仅输出阶段、数字状态码、有效性等白名单，不输出标识及载荷 |

SDK 依赖核对基线为 AppsFlyer 6.18.1、Install Referrer 2.2、ads-identifier 18.0.0；这表示本次整理所核对的实现版本，**不是永久最新版或永久受支持承诺**。实施时核查[官方 SDK 版本策略](https://support.appsflyer.com/hc/en-us/articles/115001256006-AppsFlyer-Android-SDK-release-notes)，记录最终解析版本及兼容性结果；升级后重验生命周期、监听器、Manifest 和 R8。

## 4. 核心状态与判定

| 概念 | 有效条件／用途 |
| --- | --- |
| 有效归因结果 | JSON Object 的 `af_status` 明确为 `Organic` 或 `Non-organic`，忽略大小写；缺失／未知状态均无效 |
| 媒体结果 | 有效 `Non-organic`；真实来源数据支持，不凭非空字符串猜测 |
| 本地确认完成 | 有效媒体立即完成，或 Organic 的前置 GCD／必要 Referrer 确认链已有限结束；不是补报成功 |
| 当前最终目标 | 账本 `latestResultId`；优先保留媒体，Organic 和慢缓存不能降级覆盖媒体 |
| 可靠待报 | 稳定 userId＋resultId 的报告已持久化，具备固定 reportId 和冻结 deviceId |
| 报告成功 | 后台业务响应成功且 `succeeded=true` 已成功落盘；仅 HTTP 200 不够 |
| 可复用最终成功凭据 | 当前安装最终有效媒体＋当前稳定 userId 对应该 resultId 的持久成功报告 |

进程级协调器唯一管理结果、获取机会、确认完成和重试。页面销毁、超时、重组、切换 Tab 只结束自己的等待，不重复创建协调器或重开已消耗机会。账号边界按第 8 节处理。

结果按 **source＋完整 JSON 内容** 去重，清理广告标识后参与比较。SDK 与 GCD 内容相同也保存为不同来源；前置和首页 GCD 同内容复用同一 resultId／index。真实变化可以新增结果，不设“三条结果”的上限。收到真实重复 SDK 回调仍可以产生回调事件，不能拿事件条数推断账本条数。

## 5. 启动、登录与恢复时序

### 5.1 总入口

```text
应用 Splash 首帧
  ├─ AppConfig 公共配置请求独立并行，不参与门禁，不增加等待或 UI
  └─ 目标工程既定地区／协议门禁
       └─ 恢复会话与当前账号最终成功凭据
            ├─ 有可恢复会话：验证／刷新凭据 → 首次真实 profile → 页面路由
            └─ 无会话：登录选择 → 用户有效提交 → 两段归因＋真实认证 → 首次 profile

首次首页基础页面与 loading
  ├─ 已恢复最终成功凭据：直接进入正常业务
  └─ 未恢复：必要的一次首页 GCD／Referrer → 最终结果补报成功落盘＋共享剩余1秒 → 业务
            无有效结果且有限兜底结束：继续正常业务，允许以后收到真实媒体再刷新
```

地区检查仅在 `prodRelease` 的既定入口执行；地区放行前不启动统计、归因、认证、支付及页面业务。AppConfig 是独立公共配置请求，沿用可选认证，不依赖地区、归因或登录，不因归因改造增加新的等待。若 Firebase 自动初始化会绕过门禁，按架构移除自动 Provider 并在放行后手动初始化。不能为了归因测试关闭地区／协议限制。

### 5.2 主动认证

无会话显示登录选择，允许用户选择既有的一键匿名／账号认证。只有协议及输入校验通过的真实提交才启动链路；浏览选择页、账号页、协议网页不启动。进入登录选择时同时暂停已排队的前台 SDK 启动及归因专用获取／补报，提交时按当前身份恢复。

```text
有效提交及设备身份准备
→ 归因等待最多3秒
→ 真实认证网络请求
→ 归因等待最多8秒
→ 首次真实 profile
→ 按 profile 路由
```

两段归因窗口合计最多 11 秒，地区、认证和 profile 网络另计。认证慢不能吃掉第二段 8 秒；页面重组、并发观察者共用本次 deadline，不能反复续期。新的一次明确认证提交可创建新阶段 deadline，不重置进程的 GCD 机会。有效 Non-organic 立即结束本轮本地等待；Organic 确认链有限结束后也提前结束剩余窗口；无有效结果才用阶段超时兜底。阶段超时不伪造 Organic，不清空证据。

认证成功须持久化真实会话；失败返回当前登录页重试，不自动匿名。会话恢复只验证／刷新及读取资料，不重复认证或两段等待；首次 profile 或恢复临时失败留在 Splash 提供 Retry。既定路由基线为 `profile.is_new=true` 显示 B，否则 A；不按归因、flavor 或本地假字段选面。

### 5.3 后续冷启动成功恢复

先恢复当前安装、稳定用户对应的最终成功凭据，再启用归因专用行为。命中时跳过归因专用初始化／监听、获取、SDK 重试、GCD、Referrer、补报（包括更旧待报）、归因等待、共享 1 秒及归因后额外 profile。抑制已排队／迟到的归因回调对状态的更新。

保留正常 SDK 安装／会话／业务事件统计、原有会话恢复、主动真实认证及首次 profile。SDK 统计初始化与归因监听必须可以分离。更旧待报留存审计，此成功分支不再发送；没有成功凭据的账号继续补偿。

兼容历史 schema=1，成功记录缺少 `succeededAtMillis` 仍可复用；不新增有效期，不要求远程再确认，不伪造迁移成功。只有 Organic、单份旧缓存、另一用户的成功、Referrer 原始读取成功，均不能命中。稳定账号变化后重新核对。

## 6. SDK、GCD 与 Referrer

### 6.1 AppsFlyer 生命周期及重试

SDK 在既定门禁通过后初始化，init 可使用 Application context；`start` 在主线程使用当前 **RESUMED Activity**。保存弱引用、onPause 解绑，不回退 Application 强行 start，也不让 Service 长期持有 Activity。前台初始化晚于页面 resume 时需要主动交接当前宿主，不能等一个不会再发生的首次生命周期回调。

SDK 无有效结果、失败或无效回调时持续做前台重试检查。取得有效 Organic 后转入有限前置确认，不继续重复 SDK start；媒体结果、确认链结束或抑制分支结束本轮检查。实际 start 受当前宿主、SDK 最短会话间隔及单请求在途 lease 约束，不能每秒并发发请求。后台期间不新发；已有协程取消和恢复必须维护一致状态。

SDK conversion 不提供逐请求关联 ID。缓存回调不得释放尚在途的 Launch 保护，旧请求回调不得清除新请求 lease。本地 `request_attempt` 只表示提交计数，不能等同平台网络次数或声称强制刷新成功。Launch accepted、AF UID 可读、初始化成功均不等于 conversion 成功。

### 6.2 前置与首页两次独立 GCD 机会

| 机会 | 触发 | 次数及完成条件 |
| --- | --- | --- |
| 前置确认 | SDK 返回明确 Organic | 每进程最多一次实际 HTTP；先保存／补报 SDK Organic，再查询；有效媒体立即完成，否则根据 Organic 执行必要 Referrer，有限结束 |
| 首页兜底 | 首次首页已显示基础页面，仍无媒体 | 独立再一次 HTTP；可在 SDK 从未有效成功时使用，前提 SDK ready、有效前台和真实 AF UID；先等待在途前置链结束，串行执行 |

请求 URL 形状为：

```text
GET {APPSFLYER_GCD_BASE_URL}install_data/v4.0/{实际applicationId}
    ?devkey={当前环境AppsFlyerDevKey}&device_id={当前安装真实AF_UID}
```

这里 GCD 的 `device_id` 是 AF UID，区别于业务 Android ID 和 GAID。[官方 GCD 接口](https://dev.appsflyer.com/hc/reference/gcd-get-data)定义了应用、Dev Key 与安装 UID 参数。

独立 HTTPS 客户端，根地址无用户信息、路径前缀、已有 query／fragment；路径及参数正确编码。不附业务 token、cookie、用户头和 BODY 日志；不启用自动重试、重定向或缓存。单次总超时 10 秒。只有 HTTP 成功且正文为明确有效状态的 JSON Object 才接纳；保留数据原类型，只附上本次查询实际使用的 `af_uid`，不从旧 SDK 数据拼出 first-launch／日期／广告字段。

实际发 HTTP 前记录机会已消耗；失败、无效、超时、取消均不在该机会内重试。前置尚未取得 UID、不曾发 HTTP 时可以继续等待条件；首页遇无 UID／无前台／SDK 不可用则有限结束，不让首页一直等，也不在返回／刷新／Retry 时补开新机会。再次冷启动且仍无最终成功凭据可重新取得两次机会。

HTTP 前后复查当前安装 UID、前台／启用条件及已有媒体目标，避免旧响应覆盖新目标。前置失败不取消首页独立机会；两次请求永不并发。SDK 已有媒体跳过不必要查询。

GCD 明确 Organic **也要保存及按账号补报**。首页 GCD 一有有效结果即通过更新流交付账本与待报流程，不等 Referrer 完成后才第一次保存；之后最终列表交接按同来源＋内容去重。即时交付不等于写盘完成，仍需事务成功证据。

### 6.3 Google Play Install Referrer

只有 GCD **也明确 Organic** 才辅助读取；前置路径还要求先有 SDK Organic。无 SDK 结果、GCD 失败／未知不直接调用 Referrer 猜渠道。基线通过官方 InstallReferrerClient 连接 Google Play，限定 10 秒，成功、失败、超时、取消均结束连接。

成功读取的原始结果绑定 `PackageInfo.firstInstallTime`，先同步 `commit()` 成功持久化，再做渠道判断。空串、自然、未知来源也属于成功读取，缓存复用以免重复连接；读取失败或落盘失败不伪装成功。缓存安装时间不匹配、坏 JSON 或无法取得有效安装时间视为未命中。

| 原始证据 | 判定 |
| --- | --- |
| 明确非空 `gclid` | 可升级媒体，排除 `unknown`、`null`、`undefined`、`none`、`(none)`、`not set`、`(not set)` 等无效占位 |
| 有效 `utm_source`＋已确认付费 `utm_medium` | 仅命中外置 medium 白名单才升级 |
| 仅 source、未知 medium、organic／none、冲突的重复参数、非法编码 | 不升级，不推测平台或广告系列 |

升级时建立独立 `google_install_referrer` 结果，`af_status=Non-organic`，附真实 AF UID。`media_source` 优先真实 utm_source；仅 gclid 时可用表示来源的 `google_play_install_referrer`，不能伪称某广告平台。映射 `utm_campaign→campaign`、`utm_id→campaign_id`、`utm_medium→af_channel`；缺失不补虚构值。`install_referrer_evidence` 存原始数据对象。它是自有补充证据，不能冒充 AppsFlyer callback。

## 7. 持久化字段及事务

### 7.1 存储位置及生命周期

以下路径均**相对应用私有沙箱**，不写设备用户号或电脑目录。文件名读取当前 APK 的目标配置。

| 位置／键 | 类型及内容 |
| --- | --- |
| `files/datastore/{STORAGE_NAME}.preferences_pb` | Preferences protobuf，不是 JSON 文件 |
| 上述文件的 `install_attribution_ledger_v1` | String，内部为账本 JSON |
| 同文件 `appsflyer_install_attribution` | String，当前原始结果 JSON 兼容快照；独自存在不证明已上报 |
| 同文件 `device_id` | String，业务持久设备标识 |
| 同文件 `auth_session` | String，会话 JSON；只需要 userId／epoch 时禁止导出 token／refreshToken |
| `shared_prefs/{INSTALL_REFERRER_STORAGE_NAME}.xml` 的 `successful_result` | XML String，内部为 Referrer 成功读取 JSON |

归因账本与 Referrer 缓存是两个存储，不存在跨文件原子事务。更新应用保留安装记录；卸载／清数据结束该安装记录。退出、注销和切换账号只清必要会话，不删除安装归因、按账号支付恢复及生成幂等记录。沿用 Manifest 禁止备份并显式排除云备份／设备迁移，防止把安装成功凭据迁到另一安装。账本没有独立 installId，startupId 不是安装 ID。

### 7.2 账本 schema=1

本地 JSON camelCase，HTTP snake_case。默认序列化未启用 encodeDefaults，默认值可省略，解码时按表恢复。

| 对象／字段 | 类型 | 默认／含义 |
| --- | --- | --- |
| `version` | Int | 1，模型版本 |
| `latestResultId` | String? | null，当前最终目标 |
| `nextResultIndex` | Int | 1，下一个安装内结果序号 |
| `results`、`reports` | Array | 空数组 |
| results：`id` | String | 必填，新结果 UUID |
| results：`source` | String | 必填，`appsflyer_sdk`／`gcd_http`／`google_install_referrer` |
| results：`data` | Object | 必填，来源数据；递归清除广告标识后的原 JSON 类型 |
| results：`index` | Int | 必填，安装内递增，新内容才增长，重试不增长 |
| results：`startupId` | String | 必填，创建此结果的进程 UUID，用于识别跨进程补偿 |
| reports：`reportId` | String | 必填，稳定 userId＋resultId 对应的固定 UUID |
| reports：`resultId`、`userId` | String | 必填，关联结果与稳定用户 |
| reports：`succeeded` | Boolean | false，可靠成功落盘后才为 true |
| reports：`succeededAtMillis` | Long? | null，业务成功时的客户端 Unix 毫秒值，随成功状态一起落盘 |
| reports：`deviceId` | String? | null，兼容旧记录；新报告冻结创建时身份，旧记录迁移前补齐 |

示例仅展示结构，所有 ID 为占位说明，不可作为测试真实结果：

```json
{
  "latestResultId": "example-result-id",
  "nextResultIndex": 2,
  "results": [{
    "id": "example-result-id", "source": "appsflyer_sdk",
    "data": {"af_status": "Organic"}, "index": 1,
    "startupId": "example-process-id"
  }],
  "reports": [{
    "reportId": "example-report-id", "resultId": "example-result-id",
    "userId": "example-user-id", "deviceId": "example-frozen-device-id"
  }]
}
```

无单独 pending 枚举；succeeded 缺失即 false。账本不持久化 attempts、lastError、下次重试时间、完整 HTTP 请求或 GAID；没有自动过期、固定条数裁剪或周期重归因。报告发送时从固定结果及所属用户重新构建，动态发送字段可以变化。

### 7.3 原子性与故障补偿

1. 未登录可先保存来源结果。稳定用户可用后为缺少报告的结果创建报告，**先持久化报告再 POST**。
2. 来源结果、当前目标、账号报告及旧版兼容快照在同一 DataStore edit 中提交。不能创建第二个 DataStore 操作同一活动文件。
3. 慢读盘／读盘失败不拿空账本覆盖原文件；保留内存候选，恢复后合并，媒体优先。写超时／失败不宣称可靠入队。
4. 服务端业务成功后，先提交 succeeded=true 和成功时刻；存储成功返回后才发布内存成功状态和回执。取消、超时、异常保留同 reportId 待报。
5. 若服务端已成功而客户端写成功状态前被杀，重启使用原 reportId 重发。后台必须幂等，不能依靠客户端“恰好一次”。
6. 同 userId 新 epoch／令牌刷新／冷启动复用报告；不同用户分别建档。每目标每轮最多 10 次、间隔 1 秒，耗尽保留待报和 Retry；重启／主动 Retry 开新有限轮，多个触发合并，不让多个消费者各重试 10 次。

### 7.4 Referrer 成功缓存结构

```text
first_install_time_ms: Long，当前安装 firstInstallTime（毫秒，必须 >0）
data: Object
  install_referrer: String|null
  referrer_click_timestamp_seconds: Long
  install_begin_timestamp_seconds: Long
  referrer_click_timestamp_server_seconds: Long
  install_begin_timestamp_server_seconds: Long
  install_version: String|null
  google_play_instant: Boolean
```

上述秒时间不能直接与 succeededAtMillis 相减；缺失字符串保留 null，不用当前版本／本机时间补齐。successful_result 存在不代表生成了补充媒体结果，更不代表后台已收。

以下仅在进程内：本次 startupId／stage／单调时钟起点、阶段 deadline、两次 GCD 机会、homeEntered／homeVerification、dirty 状态、有限重试计数、报告状态、callback_id／request_attempt、回执 reportedAtNanos。不为首页完成新增持久键；结果的历史 startupId 和会话自身 epoch 是各自已有持久字段。

## 8. 设备、账号与会话隔离

| 标识 | 来源及边界 |
| --- | --- |
| 业务 `device_id` | 新安装首次持久化真实 Android ID，不是硬件序列号；缺失则失败重试，不造 UUID／空值替代 |
| AF UID | SDK 的当前安装标识，用于 GCD device_id 和登录 af_uid；不可用业务 ID 或 GAID 替代 |
| GAID | 当前系统可用广告 ID，仅按需查询和发送；不表示安装身份，不落盘、不参与去重 |
| `userId` | 服务端稳定账号，报告所有权与成功恢复的隔离依据 |
| session `epoch` | 登录会话代次，防旧请求及回执跨账号／重登放行；不是报告幂等键 |
| session `revision` | 刷新凭据版本；通常刷新保留 userId／epoch，revision 增长 |
| resultId／reportId／index | 分别是来源结果、账号报告、安装内结果序号，彼此不可替代 |
| startupId | 进程 UUID，不是安装标识，也不是 report_id |

保留历史 UUID 与既有会话兼容；已有设备值普通读取不改写，只有**无会话时用户主动一键匿名登录**准备阶段才将旧 UUID 迁为当前 Android ID。迁移前同事务冻结历史报告缺失的 deviceId，已有冻结值不改。不得因为启动、账号密码登录、统计事件或退出操作顺手重置身份。

请求体、会话／认证头、`X-APP-USER-ID` 使用同一所属用户快照（EventOwner／session tag），匿名快照保持匿名头，不读取发送瞬间的新账号替换。账号变化取消旧会话在途报告与业务请求；旧回执不能释放新 epoch 门禁；旧账号报告保留以后按所属用户补偿，不能带新身份发送。

## 9. 登录及补报接口契约

### 9.1 登录 attribution 对象

匿名、账号及已存在的 Google 认证都携 attribution 对象。基线端点为 `auth/anonymous`、`auth/register`（账号注册即登录）、`auth/google`；沿用目标项目已确认接口，不能仅为归因擅改账号业务。Google 底层兼容不要求新增产品入口；刷新 token 不当作一次新登录。

登录 attribution 字段：`attribution_source`、`device_id`、`af_uid`、可空 network／campaign／campaign_id／adgroup／adgroup_id／creative／creative_id／channel／country、`platform=android`、`app_version`、`package_name`、`extra_data` Object，以及本次可用时的 gaid。没有有效归因时保留真实空证据，不填示例活动或伪造 Organic。顶层和 attribution.gaid 复用同一次查询结果。

登录来源字符串为 `appsflyer` 或 `google_play_install_referrer`；补报的 attribution_source 使用下表约定的不同大小写，不能混用。

### 9.2 `POST attribution/report`

沿用业务 API 的 base URL／可选认证约定。账号报告使用原所属稳定用户和冻结设备值；业务成功使用 `ApiResponse.checkSuccess` 等价契约，HTTP 200 且业务码失败仍是失败。

| HTTP 字段 | 类型／来源 |
| --- | --- |
| `device_id` | String，reports.deviceId 冻结值 |
| `package_name`、`app_version`、`platform` | 当前实际构建身份；platform 为 android |
| `user_id` | 所属稳定用户；不得跟随当前全局账号漂移 |
| `attribution_source` | SDK／GCD 为 `AppsFlyer`，Referrer 为 `GooglePlayInstallReferrer` |
| `network`、`campaign`、`campaign_id` | 已知才填，按真实字段映射 |
| `adgroup`、`adgroup_id`、`creative`、`creative_id`、`country` | 已知才填，Meta 层级见下表 |
| `click_time`、`install_time` | 存在时拷贝原 JSON 值，不重造或改类型 |
| `extra_data` | 该 result.data 的 Object，保持原数字／布尔／嵌套类型；广告标识例外清理 |
| `report_id` | String，持久报告 UUID，失败重试及跨进程不变 |
| `attribution_result_index` | Integer，持久 result.index，不是重试次数 |
| `attribution_result_source` | `appsflyer_sdk`／`gcd_http`／`google_install_referrer` |
| `attribution_stage` | `splash`／`post_login`／`home`；结果 startupId 不同则 `startup_recovery` |
| `startup_elapsed_ms` | Integer，发送时当前进程单调时钟耗时，非负；每次发送可变化 |
| `is_install_referrer_supplement` | Boolean，仅 Referrer 为 true |
| `is_gcd_http_result` | Boolean，仅 GCD 为 true；不与上一项同时 true |
| `gaid` | 可选 String，每次发送查询当前值，不可用省略 |

补报基线不额外发送顶层 af_uid 或 channel；AF UID 作为真实证据保留于 extra_data，channel 在登录子对象及 extra_data 中保留。不要把登录结构未经核对直接当作补报结构。

### 9.3 字段映射

| 业务字段 | 原字段优先级及约束 |
| --- | --- |
| network | media_source → network |
| campaign／campaign_id | campaign；campaign_id → af_c_id |
| adgroup／adgroup_id | af_adset → adset；af_adset_id → adset_id；非 Meta 才回退 adgroup／adgroup_id |
| creative／creative_id | af_ad → creative；af_ad_id → creative_id；Meta 才回退 adgroup／adgroup_id |
| channel（登录） | af_channel → channel |
| country | country_code → country |

Meta 判别沿用真实 is_fb=true、媒体为 Facebook Ads 或出现 adset／adset_id。Meta GCD 的 adset 是广告组、adgroup 是广告，不能映射到同一级。可用原始 primitive 转展示字段字符串，但 extra_data 仍保存原 JSON 类型；不按名称猜广告平台／国家。

### 9.4 服务端必须联调的条件

服务端按 report_id 幂等，并校验所属用户、安装／应用上下文；同一 ID 重发返回等价业务成功，不重复产生业务副作用。startup_elapsed_ms、stage、当前 GAID 可以变化，不能把整份请求哈希作为幂等身份。按安装内结果 index 与媒体优先规则防旧 Organic／迟到旧报告覆盖媒体；客户端不得发明数据库表名或假定该能力已上线。

联调至少核实：可选 GAID 的接收与不可用语义、三类来源、JSON 类型、新布尔及序号字段、重复报告响应、旧结果防回退、成功后数据异步处理与 1 秒间隔效果。缺项列为未验收，不用客户端测试替代后台实收证明。

<a id="s10"></a>
## 10. GAID 与回调事件

### 10.1 GAID 查询及隐私

Hilt 单例 AdvertisingIdProvider 在 IO 使用 `AdvertisingIdClient.getAdvertisingIdInfo`。仅共享尚未结束的查询，每个调用方最多等 1 秒；Google 阻塞调用超时后若仍运行，后续调用继续共享该在途查询，避免无限创建线程。调用真实结束立即释放结果，下次独立查询重新读取；单个等待者取消不取消其他等待者。

限制广告跟踪、null、空白、全零 UUID、非标准 UUID、GMS 错误或超时均不可用；有效 UUID 统一小写。不可用时省略 gaid，不能用旧值、Android ID、AF UID 或空串补位。调用方取消向上传播。查询位于既有登录、报告发送及事件队列中，不新增页面或首页 loading，地区检查前不额外查询。

登录顶层及 attribution.gaid 同值；补报与所有自有事件只在公共顶层带 gaid。异步事件补 GAID 不改原 event_time／userId。GAID 不持久化、不参与 source＋data 比较、安装判定、渠道升级、账号识别和 report_id 去重。

原始 JSON 的对象／数组递归删除常见广告标识键：键去掉 `_`、`-` 并转小写后属于 `gaid`、`advertisingid`、`googleadvertisingid`、`gpsadid`。历史账本及兼容快照同步清理，保留 resultId／reportId／index／source／owner／成功状态，不因为清理重报。真实 referrer 及其他证据不伪造。

所有 HTTP 日志即使常规脱敏关闭，也始终隐藏 GAID、Advertising ID、转义 JSON／query／header 中的对应值及 UUID 文本回显；release 不启用 BODY 日志。SDK 所有变体强制 setDebugLog(false)，数据类 toString 隐藏标识。白名单诊断日志不输出完整 URL、密钥、原始回调、Referrer 或事件载荷。

### 10.2 SDK conversion 回调双出口

| 真实回调 | 数数 | 自有后端 | 参数 |
| --- | --- | --- | --- |
| 有效 SDK conversion | `s_attribution_success` | `z_attribution_success` | callback_id、request_attempt、attribution_status=organic／non_organic、app_version、platform |
| SDK 失败或无效 conversion | `s_attribution_failure` | `z_attribution_failure` | callback_id、request_attempt、failure_reason、app_version、platform |

两个出口分别由 ENABLE_THINKINGDATA／ENABLE_BACKEND_ANALYTICS 控制，异常互不影响。Firebase／AppsFlyer 不发送这两类手动回调事件。GCD、Referrer、补报成败、Launch accepted、页面超时及无回调都不能伪造 conversion 事件。

回调入口冻结真实 deviceId、userId、毫秒 event_time 与参数，登录前允许匿名；自有事件发送时头部使用原 EventOwner。callback_id 是进程内计数，不是跨进程唯一 ID；request_attempt 不表示精确网络关联。参数不包含原始证据、UID、GAID、密钥或 URL。

自有 `POST events/report` 公共体：device_id、event_type、event_time、可空 user_id、package_name、app_version、platform、可选 gaid、parameters。parameters 值统一字符串，数数按其支持类型发送。该队列容量基线 256，**仅内存、不持久化且无自动重试保证**；满队列、发送失败或进程结束可丢事件。它和持久 attribution/report 是不同链路，不能用事件成功放行首页。

<a id="s11"></a>
## 11. 首页和资料刷新门禁

首页先显示基础页面和 loading，再发送一次进入信号。没有媒体且未恢复最终成功凭据时，完成首页独立 GCD 和必要 Referrer 后，才处理首页资料刷新、余额、作品／任务、模板／分类等数据。页面 Retry、刷新、返回只重试业务／报告，不重开首页 GCD。

门禁按以下顺序判断：

1. 已恢复当前账号最终成功凭据：立即返回，不依赖首页信号，不额外刷新归因后 profile，避免首页与附属业务互相等死。
2. 未恢复：必要的首页辅助确认尚未结束则继续等；即使 GCD 已即时保存且 POST 成功，也不提前越过仍在途的 Referrer。
3. 辅助确认结束且没有有效结果：放行正常业务，不叠加旧 SDK 10 秒等待。
4. 有最终有效结果：只接受**当前 epoch＋当前 resultId** 的业务成功且落盘回执，并等待共享剩余间隔；失败耗尽展示 Retry，不能拿旧成功放行。

共享时刻 T 为本次补报业务成功时刻，只有成功状态落盘后才发布回执。首页与补报后 profile 刷新各自等待 `max(0, T + ATTRIBUTION_HOME_DATA_DELAY_MS - 当前时刻)`，共用同一 T，不串联成 2 秒；首页不等 profile 成功。慢落盘已消耗的时间不能再完整追加一次间隔。

进程内使用单调时钟；非最终成功恢复分支需要重建旧成功间隔时按已持久 Unix 毫秒计算并限界，不混减纳秒与毫秒。最终媒体成功恢复分支直接跳过全部归因延迟，即便缺少时间戳。

迟到的不同有效目标取消旧首页请求，等待新目标成功及剩余间隔后刷新一次；旧响应不能覆盖新数据。按 resultId 区分同 JSON 的不同来源。补报后 profile 有限重试，每轮最多 10 次，失败保留当前真实模式及重试入口，不再次 POST 已成功报告，不重置 T，不重新登录。Splash 用于路由的首次 profile 沿用原流程，不混入此门禁。

### 14.3 解码 Preferences，再取账本字符串

不能用 cat／strings 查到片段就认定 protobuf 完整。使用目标实际 DataStore 版本的 Preferences protobuf 解码器读取离线副本；若其生成类为 `androidx.datastore.preferences.PreferencesProto.PreferenceMap`，可将以下保存为 `attribution-local-evidence/ReadAttributionLedger.java`。若版本生成 API 不同，按目标依赖提供的解码能力调整并记录，不硬找某台电脑的缓存路径。

```java
import androidx.datastore.preferences.PreferencesProto;
import java.nio.file.Files;
import java.nio.file.Path;
class ReadAttributionLedger {
    public static void main(String[] args) throws Exception {
        var map = PreferencesProto.PreferenceMap.parseFrom(
            Files.readAllBytes(Path.of(args[0]))).getPreferencesMap();
        var value = map.get("install_attribution_ledger_v1");
        if (value == null || !value.hasString()) {
            throw new IllegalStateException("账本字符串键尚不存在");
        }
        System.out.println(value.getString());
    }
}
```

通过目标工程依赖解析找到实际 jar，在本机设置 classpath（如有依赖也须包括），不使用来源工程目录。JDK 17 示例：


| SDK 请求持续 HTTP400 | 先核最终 SDK 版本和官方支持政策，再核当前应用／Dev Key、请求与平台响应；不要先认定 Key 错，也不要重写全部生命周期绕过 |
| CDN／配置 GET200，但归因失败 | 分清请求类型；资源可达不证明 install／session／event POST 被接受；SDK 本地数字错误码不等于 HTTP 状态码 |
| SDK 一直 Organic，平台已见媒体 | 核前置／首页 GCD机会、真实 AF UID、后台环境、返回内容、Meta映射；不增加5秒无限轮询 |
| 首页一直 loading | 是否错误等旧 SDK10秒、Referrer 没有限结束、未可靠入队、业务码失败、写盘未完成、epoch／resultId 不匹配、成功恢复仍等首页信号 |
| 重启重复报／新用户被旧成功放行 | 核报告先存、同 userId＋resultId 固定 ID、成功先落盘、owner 冻结及成功凭据条件；核后台 report_id 幂等与结果防回退 |
| 调试正常 release 异常 | 检查最终 Manifest、生成配置、签名、R8、序列化／Retrofit 注解与泛型、回调／Referrer 类；不能关闭混淆或安全门禁假装通过 |
| GAID缺失／后台旧账号 | 核系统限制与GMS、1秒等待、最终 HTTP 省略语义、异步 EventOwner 头体一致；不回填旧 GAID |
| 开发机换目录后命令失败 | 从目标 Gradle 根／文档包自身执行，检查占位值是否填完；按类名及实际 namespace 定位，不找来源电脑路径 |
| 构建依赖不可达 | 记录真实网络／鉴权原因，使用已确认的 HTTPS 镜像／完整校验产物，不关闭 TLS 或编造验证通过 |

发布前至少核对 C01、C02、C07、C08、C19、C24、C32、C35～C37。查看实际最终依赖和合并产物，不只阅读 source properties。检查 allowBackup、dataExtractionRules 是否被 SDK 合并覆盖；AD_ID 按实际依赖／目标版本要求合并，无重复或误删；自动初始化不得绕过既定入口。

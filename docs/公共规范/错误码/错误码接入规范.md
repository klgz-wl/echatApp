# 错误码接入规范

公共规范版本：`1.2.0`
发布日期：2026-11-02
编号字典：[错误码对照](错误码对照.md)；执行入口：[通用实施提示词](通用实施提示词.md)；文件校验：[版本清单](版本清单.json)。

## 1. 公共内容与项目内容

本规范用于多个 Android 项目共用一份编号字典、展示约定和实施提示词。它不规定品牌、包名、页面结构、具体认证范围、支付渠道或地区名单，也不把某个项目的实现与测试结果作为其他项目的验收依据。

| 内容 | 保存位置 | 维护方式 |
| --- | --- | --- |
| 编号字典、接入规范、通用实施提示词及版本清单 | 独立公共目录保存主版本；各项目同步至 `docs/公共规范/错误码/` | 同一版本逐字节一致，不加入项目特例 |
| 编号到资源、源码、入口的映射及适用性 | 各项目 `docs/错误码接入记录.md` | 按项目实际状态维护 |
| 产品需求、设计、开发计划、项目规则及历史验收 | 各项目原文档 | 保留项目内容，引用公共规范及本项目接入记录 |

项目已有同名对照表应改为公共入口或迁移后删除并修复引用，不能继续维护另一套有效字典。已有专项提示词的错误码章节改为引用本包的统一规则和提示词，其他业务章节保留。历史验收保留原批次、提交与范围，不改写成当前验收。

## 2. 展示约定

1. 保留原错误正文和原语言，在末尾追加 ` (错误码)`，即一个 ASCII 空格、左括号、编号、右括号。例如 `Please try again. (E-501)`、`Please try again. (R201)`。
2. E 码格式为 `E-` 加三位数字；R 固定码格式为 `R` 加三位数字；参数化 HTTP 码例如 `R205-403`。不得把 E-201 改写为 E201、R201 改写为 R-201。
3. 同一条提示只附一个主诊断码，重复格式化不叠加。地区错误使用检查器实际产生的 R 码，包括离线 R200，不额外追加 E-206。
4. Toast、页面错误说明、对话框及媒体错误占位等既有用户可见错误都纳入盘点；同一错误的不同展示入口遵循同一映射。原流程静默处理的异常继续静默，不为凑覆盖率新增提示。
5. 地区诊断从原有独立 `Ref: 编号` 行迁到原正文末尾，避免出现两处编号。保留原 Retry／Exit、关闭行为及安全门禁。公共规范不额外要求修改字号或页面布局。
6. 成功、普通操作、加载中、普通空态和通用 Retry 按钮不加码。若原界面只用专属短提示表达一个确定错误，例如提交未知状态的 `Retry`，可显示 `Retry (E-402)`；必须限定该错误入口，不能修改全局 Retry 资源污染其他按钮。
7. 支付等待与取消仅对原流程已经展示的提示追加 E-602、E-603，不新增通知或失败事件，不改变恢复、查单及履约判断。
8. 文案与格式使用 Android 字符串资源，翻译保持相同编号。可以按现有结构选择静态带码资源或统一格式化入口，但必须有唯一追加责任；不得在已有带码正文外再包一层编号。
9. 错误码不是原始异常输出通道。禁止附加用户数据、账号标识、IP、国家值、URL、响应正文、凭据、证书内容或原始异常；R205 只允许真实数值 HTTP 状态。

## 3. 语义映射与业务边界

先按实际触发条件确定语义，再查[错误码对照](错误码对照.md)。相同文案可能对应不同场景，不能仅搜索字符串后统一分码；不同资源也可能复用同一个语义码。后端 code 和 HTTP 状态不能直接替代公共编号。

业务操作中的会话失效或身份变化核对 E-207，生成请求明确冲突核对 E-406，生成服务或当前模式不可用核对 E-407；具体边界以公共字典为准。它们与主动认证失败、启动失败、提交结果未知和任务失败终态分别核对，不用 E-204、E-205、E-402、E-401 笼统替代。现有后端 code／HTTP 401、403、409、503 只能结合接口契约和原有分类核对，不建立脱离业务场景的全局状态码映射。

图片选择／拍摄入口失败核对 E-305，取得图片后的读取或私有副本准备仍核对 E-301。生成输入资源上传失败核对 E-408，个人资料输入和更新分别核对 E-704、E-705；头像上传属于资料更新动作，不能仅凭“上传”二字与生成输入上传共用 E-408，资料读取仍按 E-501。

生成请求在准备或创建阶段已明确未提交／被拒绝时核对 E-409；可能已提交而受理结果未知仍用 E-402，真实任务失败终态仍用 E-401。仅凭本地失败枚举、异常名、缺失 taskId 或 HTTP 数字不能确定这些阶段；复用现有请求、阶段及业务结果证据。已有会话失效、余额不足、请求冲突及服务不可用语义优先使用相应专码，不让 E-409 成为生成通用兜底。

覆盖扫描应包括既有字符串、直接 Toast／Snackbar、页面状态、弹窗、媒体回退、网页回退、动态服务端错误和兜底分支。动态错误保留项目原有安全展示策略，再按实际场景附码；不得为了“保留原文”暴露原本不展示的技术内容。未知或新语义按公共维护流程处理，不一律归入 E-205 或 E-501。

只修改必要的展示、错误语义传递、资源、适用测试和文档。不借此改变接口、会话和设备身份、归因、埋点、支付成功边界、生成幂等、重试次数、取消传播、持久化协议、包名、签名、环境或发布策略。项目没有的功能不新增；模拟或未接入的服务不冒充真实能力。不要引入与此任务无关的框架或重构。

若项目已使用不同编号，先登记旧码、公共码、语义及冲突，统一迁移展示并保留项目迁移记录；不得覆盖公共含义或让新旧字典同时生效。代码既有行为与规范冲突时，记录真实差距并做必要的最小接入，不能只改文档宣称完成。

## 4. 项目接入记录

每个项目至少记录以下内容：

- 接入的公共版本、日期、版本清单和来源；确认公共文件哈希一致。
- 实际入口清单：错误码、资源、源码位置、触发条件、展示方式、当前状态。状态区分已接入、待接入、待分配、不适用；未盘点的入口标注待核对，不能直接当作不适用。
- 旧编号或旧 Ref 行的迁移情况，动态与兜底错误的处理，重复编号检查结果。
- 本轮确实执行的验证、结果和范围；设备、后端、平台或环境阻塞分别记录。历史验证注明对应提交，不能沿用到新修改。
- 未覆盖场景、公共版本申请和后续验收项。

记录是项目事实，不复制公共语义表作为另一份规范。需求、设计、计划和 AGENTS.md 等适用入口引用公共规范与接入记录，并明确代码接入状态。

## 5. 验证与完成标准

代码接入时，先形成所有实际可达用户错误入口清单，逐项映射，不能仅凭资源搜索结果宣称全量覆盖。检查至少包括：

- 原正文和语言保持，E/R 格式正确，同语义跨入口同码，编号只出现一次。
- 地区真实 R 码不丢失，R205 参数有效，原 Ref 行已迁移，正常取消不转换为错误。
- 静态资源、动态错误、共享组件、兜底和已有短错误提示均有明确处理；成功、空态、加载中及通用按钮没有误加。
- 支付待确认／取消、任务未知／终态、账号和地区隔离等原业务语义保持，不新增重复通知。
- 会话变化、生成冲突和生成可用性提示分别核对新增编号；报价不可用仍保留原禁用逻辑，不改价格、不生成新请求、不由诊断码推导提交结果。
- 图片获取、图片本机准备、生成输入上传、请求创建及服务端任务终态按真实阶段区分；资料校验、更新和读取分别映射，不按共享正文一刀切，不把上传超时当作生成提交未知。
- 根据实际改动执行必要的语义测试、可用环境构建／Lint及项目规定门禁；涉及显示时检查长文案、换行与大字体。设备不可用则明确 UI 验证未完成。
- 公共文件整组同版本、哈希一致，项目引用有效，`git diff --check` 通过；只提交本任务文件或改动块，保留已有工作区改动。

仅文档同步时只验收内容、链接、版本及文件一致性，不执行代码实施，也不把 Android 测试或业务验收写为通过。项目环境和发布限制继续生效；本包本身不授权 prod 构建、真实扣款、发布或远程服务变更。

## 6. 主版本发布与同步

1. 由团队指定的公共主版本维护者管理独立目录。分配新码或修正规范时统一修改三份公共文档，升级版本并记录变化；不得在某项目副本单独改规则。
2. 每个版本目录包含 `错误码对照.md`、`错误码接入规范.md`、`通用实施提示词.md` 和 `版本清单.json`。清单记录版本、日期、变更摘要及前三份文件的 SHA-256；清单不包含自身哈希。
3. 对外提供 `error-code-spec-v版本号.zip`，压缩包内只有该版本四个公共文件，顶层目录为 `error-code-spec-v版本号/`。不包含项目源码、接入记录、本机路径、凭据或项目验收材料。
4. 接收者核对文件完整和清单哈希后，将四文件原样同步到项目 `docs/公共规范/错误码/`，用同一份[通用实施提示词](通用实施提示词.md)实施。不能只取表格或混用不同版本文件。
5. 已发布版本及 ZIP 保持不变；变更发布新版本。新增码、兼容性和迁移要求写入新版本摘要，各项目记录实际升级状态，不因文件已同步就自动标记代码已接入。
6. 转发时发送完整 ZIP，说明版本及主版本维护者的协作入口。接收方发现新场景回交维护者统一登记，避免多人并行分配冲突编号。

`1.2.0` 相对 `1.1.0` 新增 E-305、E-408、E-409、E-704、E-705，原有 25 个 E 系列编号和 12 类 R 系列编号保持兼容；`1.1.0` 已新增的 E-207、E-406、E-407 继续保留。迁移时整组同步四文件，核对图片获取／准备、生成输入上传／请求创建、资料校验／更新的边界并更新项目记录；原未带码记为无，若已有其他编号则记录旧码与公共码的对应及冲突。无需修改既有业务状态、协议或价格规则。同步完成与代码接入完成分别记录，旧版本及 ZIP 不覆盖。

解压后可在包目录执行以下校验；验证成功只说明收到的文件与清单一致，不证明项目完成接入：

```bash
python3 - <<'PY'
import hashlib, json
from pathlib import Path

root = Path('.')
manifest = json.loads((root / '版本清单.json').read_text(encoding='utf-8'))
expected = {'错误码对照.md', '错误码接入规范.md', '通用实施提示词.md'}
assert set(manifest['files']) == expected, '公共文件清单不完整'
for name, digest in manifest['files'].items():
    actual = hashlib.sha256((root / name).read_bytes()).hexdigest()
    assert actual == digest, f'文件不一致：{name}'
print('公共文件校验通过，版本：' + manifest['version'])
PY
```

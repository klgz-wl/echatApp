# 通用实施提示词

公共规范版本：`1.2.0`
发布日期：2026-11-02
配套文件：[错误码对照](错误码对照.md)、[错误码接入规范](错误码接入规范.md)、[版本清单](版本清单.json)。

使用方式：将完整公共包交给实施者，在目标项目中使用下面同一份正文。正文不需要替换项目名、包名或本机路径；项目事实由当前仓库自动核对，并写入项目接入记录。先按接入规范核对包内哈希。本提示词用于后续代码接入；单独制作或同步本公共包不代表已经执行它。

本版相对 `1.1.0` 新增 E-305、E-408、E-409、E-704、E-705，旧编号及语义保持兼容；`1.1.0` 新增的 E-207、E-406、E-407 继续保留。升级时整组替换四文件，核对图片获取／准备、生成输入上传／请求创建、资料校验／更新的场景和既有编号冲突并记录迁移状态；只同步文件仍不表示代码已接入。

## 可直接复制的实施正文

请在当前项目实施统一用户可见错误码规范，完成公共文件同步、代码接入、项目文档更新和适用验证。执行依据为随附公共包内同一版本的《错误码对照》《错误码接入规范》和本提示词；先核对《版本清单》的版本及 SHA-256，缺件、混版或不一致时先取得完整公共版本。

1. 先阅读当前项目适用的 AGENTS.md、需求、设计、架构和环境限制，检查 Git 状态并保留已有改动。核对真实代码，不把其他项目的功能、资源名、架构或验收结果复制为本项目事实。本任务只做错误码接入所需的最小改动。

2. 将本版本三份公共 Markdown 和《版本清单》原样同步到 `docs/公共规范/错误码/`。公共文件不得增加品牌、包名、项目资源映射、实施状态或测试结果。原有对照表迁移为公共入口，修复相关引用；旧专项提示词的错误码条款改为引用本公共规范和统一提示词，避免同时维护不同规则。

3. 盘点所有实际可达的既有用户错误提示，包括 Toast／Snackbar、页面错误、对话框、媒体／网页回退、动态错误、默认分支及专属短错误提示。按触发条件和业务语义映射公共编号，同语义同码，不仅按文案匹配。项目不存在的功能不新增，未核对的入口不能直接记为不适用。业务操作中的会话失效／变化、生成请求冲突、生成服务或模式不可用分别核对 E-207、E-406、E-407，按公共字典区分主动认证失败、启动失败、提交未知和任务终态；不能仅按 401／403、409、503 数字选码。 图片选择／拍摄入口失败、生成输入资源上传失败、明确未提交／被拒绝的生成请求、资料输入校验失败和资料更新失败分别核对 E-305、E-408、E-409、E-704、E-705；本机图片准备仍用 E-301，资料读取仍用 E-501，不能按共享正文或“上传”字样统一分码。

4. 保留原正文与原语言，在末尾恰好追加一次 ` (错误码)`，例如 `Please try again. (E-501)`、`Please try again. (R201)`。文案与格式资源化，各语言编号一致。选择符合项目现有结构的唯一追加入口，检查静态带码资源与动态格式化组合，防止重复编号。通用成功、操作、加载、空态及 Retry 按钮不加码；确定错误入口的专属短提示按公共规范处理。

5. 地区错误显示检查器实际产生的 R 码，含 R205 的真实数值 HTTP 状态；将旧独立 `Ref: 编号` 迁到原正文末尾，不保留第二处编号，不叠加 E-206。保留原名单、信号优先级、重试、取消传播、门禁及 Retry／Exit 行为。非地区错误不借用 R 码。

6. 不展示敏感数据、URL、响应正文、凭据或原始异常。动态错误沿用现有安全文案策略，再按场景附码。支付等待和取消只有在原流程已经提示时才追加对应状态码，不新增通知或事件。任务未知、刷新失败和真实终态保持原语义；会话变化、明确请求冲突及生成可用性错误不改变受理结论，不自动清理会话或重新建任务，报价不可用保留原禁用与价格校验。 仅生成输入资源上传失败不能推出生成请求已提交；使用 E-409 须有尚未提交或明确拒绝创建的证据，受理结果不明仍用 E-402，不能仅凭本地失败状态或缺失 taskId 推导。资料校验和更新沿用原规则，不更改上传、保存或回滚行为。不得更改认证、会话身份、归因、支付、生成幂等、数据协议、配置、签名、包名、环境或发布策略，不新增与任务无关的重构或依赖。

7. 如遇公共表未覆盖或旧编号语义冲突，记录触发条件、业务语义、旧码及不能复用的原因，交由公共主版本统一维护；取得新版本后整组同步。不能自行占号、改公共含义或把所有未知错误塞入 E-205／E-501。未能取得新版本的场景记为待分配、待接入，并在最终结果列为未完成项。

8. 新建或更新 `docs/错误码接入记录.md`，记录公共版本、来源、文件一致性、每个实际入口的编号／资源／源码／展示方式和接入状态。按事实区分已接入、待接入、待分配、不适用及待核对。项目需求、设计、开发计划、规则及适用索引引用公共规范和本项目记录，修正矛盾的旧展示要求。资源映射、项目特例、实施与验证结果只写项目文档；历史验收保持原提交和范围。

9. 验证实际入口覆盖、原文保持、E/R 格式、单次追加、多语言、动态兜底、地区真实分类及业务语义。 重点验证图片获取与准备、生成上传与请求创建、未知受理与任务终态、资料校验与更新的分流；不得把正常取消当作 E-305，或把上传超时当作 E-402／E-407。执行项目要求且与改动相适应的检查、测试、可用开发变体构建和 Lint；遵守本项目环境限制，不擅自构建 prod、发布或触发真实扣款。界面检查包括换行和大字体；设备或外部服务不可用时明确未完成范围，不能用编译替代运行验收。

10. 检查公共四文件与所用版本逐字节一致、Markdown 引用有效及 `git diff --check`。遵守本项目分支、审查、中文提交与推送规则，只暂存本任务明确路径或改动块，保留他人改动，不强制推送或改写历史。最终报告公共版本及文档入口、覆盖情况、真实验证结果、未完成项、提交哈希与远程分支；不能只因文档已复制就宣称所有错误已完成接入。

| 身份迁移 | 无会话主动匿名提交才迁 UUID；替换前同事务冻结所有历史报告缺失 deviceId |
| 结果与报告 | schema=1、小写来源、递归清理广告标识、固定 resultId/reportId；按最新目标判定成功恢复 |
| 首页 | core HomeAttributionGate；进程级有限辅助确认与可重试存储分离，当前 epoch/resultId 和共享剩余间隔；本次成功后继续接纳真实新目标 |
| 回调 | SDK 入口冻结 owner/time；数数使用 SDK 的显式时间接口；自有回调队列仅内存、无自动重试 |
| 隐私 | SDK debug 硬关闭；广告标识强制脱敏；安装状态显式排除备份与设备迁移 |

旧入口说明已更新为 [attribution-startup](attribution-startup.md)。业务错误码合同继续沿用。为保证统一存储的会话隔离，支付侧刷新不能恢复已退出或已替换的 host，会话同步直接读取当前权威会话；不改变收费、订单或支付履约规则。地区检查按规范限定为配置启用的 prodRelease。

### 2026-11-04 项目接口字段扩展

按用户明确要求，独立 `POST /api/v1/attribution/report` 在真实值非空时增加顶层 `af_uid` 与 `channel`；沿用现有 `af_channel → channel` 映射，原始证据继续保留在清理广告标识后的 `extra_data`。独立 HTTP 客户端增加 `X-AF-UID`，值取同一份报告体中的冻结 UID，不读取当前全局 SDK 身份。缺失值省略。此项覆盖公共规范 1.0.0 第 9.2 节“不额外发送顶层 af_uid 或 channel”的项目基线；公共文档包保持原样。

## 真机迁移证据

已在一台授权 Android 15 真机以覆盖安装保留旧数据升级 dev。升级前读取旧 XML，升级后使用当前 DataStore 版本的 Preferences protobuf 解码器读取实际私有文件，不使用 strings 猜测。

- 旧账本有一份 Non-organic 结果、一份成功报告。
- 升级后 resultId 的 SHA-256 截断摘要仍为 70d6ae1177d4；reportId 摘要仍为 9c312beaa779。
- result.index 保持 1，succeeded 保持 true；source 从旧大写枚举规范化为 appsflyer_sdk。
- 迁移比对阶段未清数据、未重置广告 ID，未通过伪造缓存生成成功。正常 SDK Launch 请求继续可用。
- 上述只证明该安装的覆盖迁移与恢复，不证明所有投放、杀进程、服务端幂等或正式发布场景。

后续 connectedAndroidTest 的 UTP 工具在收尾时自动卸载了 dev 目标包，清除了这台测试机的本地登录态。该行为发生于迁移比对之后；本记录不将重新安装视为原安装延续，也不通过写入缓存重建成功。本次未调用账号删除接口。收尾重新部署 dev，用户需要重新登录。后续在需保留真实数据的设备运行 instrumentation 前，应先使用隔离测试设备或核实并配置测试工具的保留安装/数据策略。

真机定向 UI 测试结果为 10 tests、0 failures、0 errors。该机 MIUI 拦截测试宿主 Activity 的后台启动，ActivityTaskManager 记录启动结果 102；通过 ADB 显式前台启动测试宿主后继续完成，没有修改系统权限或安全开关。首轮中止及编译阶段失败均不能算通过，以上结果来自最终完整测试 XML。

| --- | --- |
| R01 | userId/epoch 固定所属，401 恢复、重放、返回均校验；真实 profile 和 token refresh HTTP 支持取消 |

# 交给新项目AI的第一条提示词

先读取本包README、完整重建提示词、源码/模型/配置清单和验证报告，以及目标 `.core-scaffold/project.json` 和 `docs/core-rebuild/开始重构.md`（若存在）。有 `developer_confirmed=true` 的脚手架参数时沿用已有确认，直接继续已授权的实现，只补问新增冲突或缺失项；不要再次等待同一确认。手工入口尚无必要参数时先检查资料并完成以下问答，再生成业务代码。

请向开发者集中询问下列内容，汇总已回答项，缺失项才追问：

1. 项目名称、目标目录、新建或已有工程、宿主模块、app与core的namespace及版本策略。
2. 新增字段前缀的准确拼写与大小写。必须由开发者确认，禁止默认VEX_或V。
3. 是否全量保留Core能力；已有模块冲突、业务协议、公共配置和存储/品牌适配的选择。
4. 是否已收到完整dev配置与独立开发签名附件、JDK/SDK及测试设备条件。dev包名固定yumo.achat.app，不要求重新提供包内已有SDK参数。
5. prod正式资料是否已有；没有则记录DEV_REUSE，先完整复用dev，之后由开发者确认正式包名、地址、Firebase/SDK及正式签名再替换。

输出“项目项、最终值或私密位置、来源、状态、开发者确认”表，复用已有确认，只有缺失的必要参数等待确认。密码/私钥不向聊天索取；读取开发者提供的本地路径或环境变量。prod正式信息待提供不阻塞dev和明确标记的临时prod开发；缺dev私密附件或设备只阻塞相应验证，不阻塞已授权的源码开发。

确认后先建立新旧职责映射和schema=2 Model改造台账，格式见templates/Model审查与改造方法.md。既有100个自有模型只是参考基线清单；拆分/合并登记baseline_mapping和全部真实目标类型，不能按固定数量机械生成或删映射漏能力。结构和1–5字段只在重构时随机一次，所有范围内模型需要实际序列化及比较/copy/恢复测试，实际功能不变。目标完成model-plan.json和refactor-review.md后运行verify --refactored与pack；不能用模板样例通过代替全量重构。

目标根AGENTS.md必须包含每次完成任务自动中文git commit和git push的规则；保留已有规则和.git/远程，仅暂存本任务文件并先验证。推送upstream或origin同名分支，不force push；无远程或推送失败保留本地提交并如实报告。具体边界见完整提示词“目标项目的Git任务规则”。

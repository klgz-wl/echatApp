### 2. 模块与技术边界

- `core` 使用 Android Library，Kotlin、Coroutines/Flow、Hilt、Retrofit/OkHttp、kotlinx.serialization；包含领域模型、Repository、协议 DTO、存储与业务协调器，不依赖 app 的 BuildConfig、Compose 页面、导航或主题。
- `app` 负责生成配置并注入、Application/Activity 生命周期、ViewModel、页面、Google 凭据获取、原生选图、支付 WebView/浏览器和导航。统计 SDK 的实现放独立 `integration` 模块，Core 只依赖接口。
- Core 不是纯 JVM 或跨平台库：图片准备、DataStore/SharedPreferences、Billing 使用 Android 能力。需要完全无 Android 的领域层时，可继续拆模块，不能把现有 Android 依赖描述成纯 Kotlin 兼容。
- 保留独立 `core`，不并入 app。现有包 `config`、`network`、`auth`、`attribution`、`analytics`、`catalog`、`visual`、`wallet`、`billing`、`payment`、`region` 是能力索引，新项目应按职责重新划分包，允许拆分/合并类与方法、多参数改为类型化 Model；提供新旧职责/公共接口映射。协议、存储、时钟、SDK 和待替换 Repository 可注入替身。
- 长期状态暴露不可变 StateFlow；一次性失败用不重放的事件流，不能把持久错误字段直接当 Toast 事件。所有异步结果都必须检查会话归属。
- 用户可见文案由宿主资源文件映射，Core 返回类型化结果；日志与协议字段不作为用户展示文案。外置可变配置，禁止用一个 Kotlin Constants 对象代替配置文件。
- 取消协程必须继续抛出 CancellationException；只对已受理交易的必要落盘或消费收尾使用有明确边界的取消保护。页面退出不能把远端在途操作当作已取消。

#### 2.1 所有 Model 的冗余字段规则

- 范围为功能包内全部自有请求/响应 DTO、领域/持久化/状态/配置值模型及新参数 Model，包含 internal/private、嵌套和有数据的 sealed 分支。枚举、接口、异常、无数据单例及第三方 SDK 原生类不强行添加。建立台账，不仅按 data class 正则计数。
- 每个 Model 随机增加1–5个字段；数量、名称、取值规则在此次重构生成后固定，后续编译不重抽。属性名与实际序列化名都采用开发者确认的前缀，校验已有属性/SerialName/继承冲突，无预设项目缩写。
- 值可以是对象创建时生成的随机值，或原字段按不同组合/顺序/分隔符 join。例如 User 的 id/name/age 可以组合 id+name+age、id+age、id+age+name；记录 null、格式和长度规则。只引用原字段，不引用其他新增字段，不拼接整对象 toString。
- 排除密码、Token、密钥、购买凭据、媒体/支付URL等敏感源；没有安全原字段时使用无业务意义随机值。新增字段不参与业务判断、金额、签名、幂等、缓存键或排序。
- 对象随机值在创建后固定，序列化不重随机，同一请求重试使用同一值；需要恢复的记录持久保存，解码保留现有值，旧记录/响应缺字段使用默认值。
- 全部新增字段参与实际序列化，不能用 Transient 排除。保证默认值也按要求输出，优先字段级/局部编码策略，不能全局开启默认值而意外改变旧业务字段。原本不可序列化的自有模型补明确 serializer/值映射，运行时句柄不能直接序列化，不以复杂为由漏模型。
- 新字段不得改变业务 equals/hashCode、集合、StateFlow去重语义；检查 data class 自动比较/复制。字段放类体也需明确 copy 保留/重算规则和恢复行为，通过显式比较、复制或映射保持既有业务语义。
- 后端兼容前缀冗余字段已确认，网络DTO实际JSON需输出；不要求响应一定回传。GET/multipart/WS/第三方SDK原生参数保持各自契约，不把“模型可序列化”等同所有协议都能新增参数。手写Map/JsonObject/存储路径逐一登记，防止实际传输遗漏模型字段。
- 自有模型扩展前缀与四端埋点事件前缀互不替代；不改归因 extra_data 原类型、SDK支付参数或收入规则。每个Model提供字段/公式/默认值/序列化/比较/copy/验证记录。

#### 2.2 Model实现与台账的执行约束

以目标实际类型为单位添加1–5字段；基线100项只是起始清单，额外检查templates生成的状态类、值映射DTO、新参数Model及目标新增类。模型合并后只给实际目标一组字段；拆分后的每个实际目标各有一组。使用 `model-plan.json` 的schema=2、models和baseline_mapping记录多对多来源，格式及完整样例见templates/Model审查与改造方法.md；不能为了通过一对一旧校验器保留无用类，也不能删除基线映射掩盖功能丢失。

业务比较应保留原模型的结构相等或引用相等规则，并排除扩展字段，不能把所有普通类改为结构相等。按原调用点核对copy、componentN解构、toString、集合和StateFlow；扩展值变化不能触发业务状态变化或把敏感原字段加入日志。只读getter、注释中的字段名或未使用的serializer不算完成实际序列化。

随机值由显式创建入口生成一次；缺失字段的旧响应/旧记录采用确定默认值，不在反序列化默认表达式中重新取随机值。join固定数字格式、null表示及长度上限。若仓库/鉴权层重建DTO再重试，必须传递原扩展快照；不只测试同一个对象重复encode。旧解码→copy/适配→持久化→进程恢复→请求重试都要覆盖实际路径。

区分自有DTO和外部载荷：自有PaymentSdkParams等包装Model仍纳入扩展和局部序列化；传给Play/第三方SDK时只投影其原协议字段。SDK原生类不改；metadata、归因extra_data、埋点parameters等原始字典内部不随机追加键。自有外层JSON扩展按后端兼容约定输出，GET/multipart/WS保持原契约，手写补报/Map路径须登记模型映射和实际输出位置。

对包含Activity、ProductDetails、回调、Throwable等运行时对象的Model，使用有界值快照与明确恢复/重新查询入口，不能假造可用句柄；新增值快照Model也纳入台账。配置与会话可序列化不等于允许上报或记录它们，序列化结果仅在规定的本地存储/测试路径使用，禁止为证明编码成功把完整敏感对象打印到日志。

不得在普通同步/dev配置阶段读取缺失的正式秘密。FORMAL必须由开发者提供并确认正式包名、匹配Firebase/SDK/地址和独立正式签名，readiness拒绝DEV_REUSE或未确认占位通过正式发布流程；不因签名文件恰好存在自动改用它。LEGACY不把备用SERVICE地址为空当正式缺口。临时prod可复用dev开关；下文“prod默认/地区门禁”描述Vexora正式基线，最终新项目正式开关需确认，不把临时dev策略冒充正式策略。

空支付基址表示 SERVICE 不可用，不阻塞纯 LEGACY；缺失支付配置不能猜域名。给所有可调阈值补合理范围校验。日志使用 OkHttp 标签的 HttpLoggingInterceptor BODY/NONE，保留耗时与追踪头；脱敏只改日志副本。复用dev配置中HTTP_LOG_REDACTION=false，完整日志仍由Debug和显式开关共同控制，release关闭；prod脱敏策略单独确认。已授权dev SDK配置在配套文件提供，密码/私钥仅私密附件；不把秘密或真实日志样本写入提示词。

### 4. 网络与认证

提供公共认证客户端、受保护业务客户端、独立支付客户端：

1. 业务响应为 `{code,message?,data?}`，code=0 才成功；要求数据的调用在缺少 data 时失败。退出等无数据操作仅检查业务成功。支付使用独立封装，不能沿用必填 code 模型。
2. 公共请求头兼容基线协议：`X-Package-Name`、`X-Platform`、`X-App-Platform`、`X-App-Version`、`X-Version`、`X-AF-UID`、`X-Device-ID`、`X-APP-USER-ID`；头部平台为 `Android`，请求体 platform 为 `android`。新后端如有不同协议，在适配层明确映射。
3. 登录、匿名、Google、刷新走不附加 Bearer 的公共认证 API。受保护请求使用当前会话 Bearer，并可用请求 Tag 固定操作所属会话。
4. Session 至少包含 token、refreshToken、userId、epoch、revision。每次成功登录生成新 epoch，同一会话刷新仅递增 revision；同账号退出后重新登录也视为新会话。先持久化成功再发布状态。
5. 底层Session只从磁盘恢复一次；正式启动仍要求联网并每次执行真实匿名认证，已有会话不跳过认证或profile，断网留Splash重试。安装 deviceId 持久生成，与用户账号无关。会话清除不删除 deviceId 和安装归因。
6. 并发 401 合并为一次刷新；等待者复用新 revision。刷新使用独立公共客户端的同步调用，避免受保护请求与刷新递归或占满同一异步执行池。原请求最多重试一次。
7. 刷新接口明确返回 401/403、缺少可用身份或返回不同 userId 时，按会话版本条件失效；网络错误不冒充退出。旧 epoch 或旧 revision 的失败不能清除新会话。
8. 支付服务重试后仍返回 401，不足以证明主业务会话失效；只有真实刷新失败走公共会话失效逻辑。支付客户端禁用连接失败自动重试和重定向，设置总请求超时；业务建单客户端同样禁用隐式重试及重定向。
9. 认证操作串行。正式A/B均只anonymous；底层保留login/google供契约兼容，账号trim、密码不trim、Google idToken非空，全部携带真实attribution；不新增旧登录选择页。
10. 正式设置不提供退出/注销菜单；若保留底层操作，先调用真实接口，失败保留会话；成功后在原 epoch 内清理用户缓存并清除会话。清理失败也必须保证已退出的会话不继续有效，同时报告清理问题。安装归因和需要恢复的交易归属记录不能混入普通用户缓存删除。

接口基线（均相对业务 API 基址）：

| 方法与路径 | 请求与结果 |
| --- | --- |
| POST auth/login | username、password、device_id、package_name、platform、version、attribution |
| POST auth/anonymous | device_id、package_name、platform、version、attribution |
| POST auth/google | id_token、device_id、package_name、platform、version、attribution |
| POST auth/refresh | refresh_token；返回 token，可返回刷新后的 refresh_token/user_id |
| POST auth/logout / auth/delete-account | 受保护、绑定原 Session；业务成功后清理 |

登录成功必须得到非空 token、refresh_token、user_id。刷新可沿用旧 refresh_token，但不允许改变账号。正式采用AnonymousStartup：联网→归因等待→再次联网→Session恢复→anonymous→GET user/profile。profile必需布尔is_new决定B/A，失败/缺失不默认A，留Splash Retry；UserProfileRepository串行刷新、前后校验epoch，公开ProfileMode状态。姓名头像展示仍可mock，不能覆盖真实模式。

### 5. 归因、SDK 生命周期与统一四端埋点

#### 5.1 SDK 与启动顺序

- 当前参考实现锁定 AppsFlyer 6.18.1、Install Referrer 2.2，SDK适配位于integration。迁移前核对官方支持周期和目标工程最终依赖，不从旧参考工程照搬6.12.2，也不把HTTP400直接归结为Key错误。
- 首帧Splash→可配置地区准入→创建业务依赖/初始化统计→等待真实归因→真实匿名登录→profile→首页。基线仅prodRelease启用地区检查；其他变体不检查。被拒或查询失败时不运行统计、归因、认证、支付恢复、任务轮询和页面请求。Firebase自动初始化Provider不能绕过准入。
- AppsFlyer第一次及重试start必须使用已获准、当前RESUMED且未finishing/destroyed的Activity；暂停解绑、单例弱引用、主线程串行请求。后台暂存启动意图，前台到来再提交；不回退Application Context。SDK init注册监听器可用应用Context，不能混淆init和start。
- 分开记录AttributionStartStatus和ConversionResult：REQUEST_ACCEPTED只表示SDK请求被接收，只有有效ConversionListener回调才归因成功。启动状态含NOT_REQUESTED/WAITING_FOR_ACTIVITY/START_CALLED/REQUEST_ACCEPTED/REQUEST_FAILED/INITIALIZATION_FAILED/DISABLED，仅保留数字错误码。
- AppsFlyerConfig分离完整debugLogging和diagnosticLogging；后者可在devRelease开启，只记阶段、数字错误码、有效性，不含标识/凭据/载荷/原始错误。prod默认关闭；完整SDK/HTTP日志受Debug开关约束。
- 升级后检查合并Manifest、权限、consumer规则、allowBackup/fullBackupContent/dataExtractionRules，基线禁止备份/迁移。版本号改变不等于运行时已修复，必须核验最终APK/AAB与真实请求/回调。

#### 5.2 Core 归因与模式分离

- ConversionSource提供conversion: StateFlow<Pending/Success/Failed>、startAttribution/retryAttribution、AF UID/广告ID读取。AttributionCoordinator只负责awaitInitial(): Boolean、forLogin()和snapshots，不再暴露resolveMode或用Organic选面。
- 首次等待5000ms，有效回调返回true，失败/超时返回false只放行认证；进程级额外调用重试最多10次、间隔5000ms，后台实际start由SDK适配等前台。首次等待结果固定，迟到有效数据通过snapshots和后续载荷体现。
- af_status为organic/non-organic只表示数据有效。缓存异步读取不能覆盖先到的回调；forLogin限时等待缓存200ms。无有效数据用空extra_data，不伪造Organic。缓存只服务登录载荷，不代表当前SDK请求成功，不决定A/B。
- 登录字段：attribution_source=appsflyer、device_id、af_uid、network、campaign、campaign_id、adgroup、adgroup_id、creative、creative_id、channel、country、platform=android、app_version、package_name、extra_data。
- 映射优先级：network取media_source/network；campaign_id取campaign_id/af_c_id；adgroup取af_adset/adgroup；adgroup_id取af_adset_id/adgroup_id；creative取af_ad/creative；creative_id取af_ad_id/creative_id；channel取af_channel/channel；country取country_code/country。
- attribution.device_id优先可用广告ID，受限/空/全零则回退持久安装ID；外层登录device_id始终安装ID。af_uid优先SDK UID，再用回调值。extra_data保持数字/布尔/数组/嵌套/null原类型。
- AttributionReports.start幂等监听有效snapshots与epoch，调用公共POST attribution/report。补报载荷顶层有device_id/package_name/platform/app_version、可选user_id和归因维度、click_time/install_time、extra_data；attribution_source按该接口为AppsFlyer（与登录小写不同），device_id用安装ID。不要直接把登录DTO当补报body。
- 补报成功后对同epoch刷新GET user/profile；is_new=true→B，否则A，同一进程可更新共享模式，不重新登录。首次profile失败留Splash；迟到刷新失败保留最后真实值。对每组快照/epoch有限重试，补报成功但profile失败时只重试profile；新快照/epoch取消旧组。补报没有持久队列或严格一次交付保证。

#### 5.3 统一业务事件与自有后端

- Core提供EventTracker.track(name, parameters, userId?, onceKey?)，业务代码不直接依赖SDK。生产由app的BusinessEventQueue实现，NoOp仅用于测试/明确关闭；AnalyticsSink提供initialize/identify/event，AnalyticsPolicy独立开关四端。
- BusinessEventQueue为有界内存Channel，入队时补event_id/event_time/session_id/app_mode并固定userId；成功入队后才保存账号+onceKey哈希去重，历史键有上限。事件本身不持久，去重存在不代表已上传成功。
- app的AnalyticsHub在准入后初始化已启用四端、启动归因补报、订阅会话与事件；过滤其他账号的迟到事件，支持匿名事件，临时绑定事件用户后恢复当前用户，各端异常隔离。公共参数补device_id/user_id/app_version/platform。
- 所有手动业务事件投递到启用的数数、AppsFlyer、自有后端、Firebase，不按平台分流。sink分别加s_/a_/z_/f_前缀，调用方必须传无前缀名；eventName直接拼接，不会检测或去除已有前缀。自动SDK采集保留原名。purchase_custom已改为payment_custom；save_video当前无功能，不造事件。
- analyticsParameters只接收合法键和标量：键匹配[a-zA-Z][a-zA-Z0-9_]{0,39}；Boolean转1L/0L，整数转Long，有限浮点转Double，字符串截100字符，最多前25项。业务调用方负责排除凭据、媒体/支付URL、原始服务错误；格式过滤器不是敏感数据识别器。
- BackendAnalyticsSink通过当前flavor业务API的公共客户端POST events/report（不走独立payment-api），支持登录前匿名、无Bearer。请求body为device_id/event_type/event_time/user_id?/package_name/app_version/platform/parameters；参数值转字符串，platform=android，毫秒event_time，事件名z_前缀。成功要求HTTP成功且code=0，Unit data可空。
- BackendAnalyticsSink有独立有界内存队列，冻结事件用户/触发时间/参数，后台IO消费者顺序发送；满队列丢弃新事件，单次异常不终止后续发送。不持久化，不做应用层重试，不保证必达。公共客户端身份头仍在发送时构造，不可宣称整个HTTP请求都使用入队快照。
- 自有业务埋点不是内容Report功能，也不是归因补报或支付client-events。支付遥测队列继续独立持久化/按账号重试，不能被业务埋点内存队列替代。

#### 5.4 支付与生成事件保持真实语义

- 四端采用af_price/af_currency/af_content_id/af_order_id/af_success/af_content_type；业务商品package_id、Play SKU af_content_id、业务订单af_order_id区分。取消/pending/unknown/closed独立状态，不能只根据af_success=false统计失败。
- paymentResult统一发pay_result和payment_custom，onceKey分别追加:result/:custom。仅status=success且google_play、price_source=google_play、有有效Play价格与币种的payment_custom带af_revenue；价格来自ProductDetails，未知历史金额/第三方catalog_quote不推算收入。pay_result和purchase_client兼容事件不带收入。
- Play统计success阶段为play_consumed，不改变“消费不等于钱包发币”的业务边界；恢复与当次消费共用订单去重键。SERVICE只在paid+fulfilled时确认第三方成功，PaymentRecord可存quotePrice/quoteCurrency用于af_price但不是实付凭据。
- CoinPurchaseController原CoinPurchaseTelemetry/events、PaymentEventQueue原PaymentAnalyticsEvent/events已删除，直接注入EventTracker；重建不要再接第二条统计流造成重复上报。购买入口source、packageId随流程透传。
- GenerationRequest增加source；提交受理报告upload_img_result的task_submit阶段；submit/refresh/pending检查终态并发generate_result，按generation:{taskId}:terminal去重，合法时间计算duration。读取pending也可能产生统计副作用，宿主无需重复报告终态。

### 6. 模板目录与媒体

- 定义 HOME/VIDEO/IMAGE 频道、VIDEO/IMAGE 媒体、分类、模板、媒体尺寸/MIME/URL、可选视频时长、声音/NEW 标志、fast/quality 报价与分页结果；新增cover映射preview_url、tags、isHomeFeatured。列表优先cover，详情preview仍为file_url；previewMediaType按URL路径扩展名推断独立预览MIME，不能把视频模板的WebP封面当视频。API 没提供的描述、声音、NEW 等信息不按名称或热度自行推断。
- 首页频道媒体由配置决定。视频首页请求 `home_featured=true`；VIDEO 列表及分类筛选显式 false；图片模板与分类接口不携带这个视频专属参数。分页、刷新、重试保持同一频道条件。
- 第 1 页请求分类，按 sort_order 排序、按 ID 去重，附加由宿主资源映射的 All 项。失效分类回退全部；后续分页保持选定分类，不拿第 2 页空分类结果清空 UI 分类。
- 模板请求必须校验分页元信息；对个别无效媒体条目可跳过并记录数量，保留同页有效条目。模板要求非空 ID、正尺寸、有限非负 duration、HTTP(S) 文件地址、图片或视频 MIME；结果按 ID 去重。hasMore 根据原始分页结果计算，不能因过滤后的数组较短提前结束。
- 作品允许 width/height=0 表示未知；未知比例不能用于除法布局。远端媒体加载检查 HTTP(S)，拒绝 localhost、回环或无效地址。新增更严格校验应记录为目标项目改进。
- `prices.fast`/`prices.quality` 使用可空 Long；零可提交，缺失、负值或未知质量不可提交。没有报价不回退 mock 或旧固定扣币数。源数据和显示资源名显式区分，服务端名称不当作 Android 资源 ID。
- 仅测试与 Debug 预览可绑定 fixture Repository，支持延迟、空态、失败次数；正式绑定 API Repository，网络失败不能静默改用 fixture。

### 7. 图片准备、生成任务与作品

协议基线：modality 只能由枚举映射成 image/video，不能接受外部 URL 作为路径。

| 方法与路径 | 请求/关键字段 |
| --- | --- |
| GET visual-generation/{modality}/categories | 分类 id、name、sort_order |
| GET visual-generation/{modality}/templates | page、page_size、category_id、可选 home_featured；items/page/page_size/total |
| POST visual-generation/{modality}/tasks | multipart：template_id、quality、image；请求头 Idempotency-Key |
| GET visual-generation/tasks/{id} | 查询 task_id 对应任务 |
| GET visual-generation/resources | 作品固定resource_type=generated；选图网格固定resource_type=upload且modality=image；各自分页 |

1. 宿主先请求UploadedPhotoRepository.photos展示已有upload图片网格，[+]才启动原生照片选择器；选已有图片通过无业务身份头的独立Streaming下载接口取得内容。Core提供prepare(Uri,userId)及prepare(InputStream,userId)，都复制到私有目录，调用方关闭下载流。复制时累计字节并检查取消，使用真实解码边界验证 MIME、尺寸和非空内容，拒绝超限、无法读取或无法识别的图片。临时文件失败清理，不仅相信文件扩展名。
2. 文件使用账号哈希与随机 ID 命名，不在索引文件名写裸 userId。SourcePhoto 保存私有文件名、MIME、宽高、字节数；解析文件名拒绝路径穿越。GenerationStorage 使用每账号索引与原子写入，提供 read/write/photoFile/clear，以及图片 prepare/discard 能力。
3. GenerationRequest 保存持久请求 key、userId、模板快照、quality、SourcePhoto、submitted、task、failure、homeNoticeDismissed、source。草稿交给宿主管理；提交前必须落盘同一 key，再发送请求。
4. 同 key 重试不能改变模板 ID、媒体种类、质量和源图；已存在 task 时直接复用。发送前检查有效报价、文件存在及长度匹配。图片直接放任务 multipart，不额外调用 files/upload。
5. 同一请求超时或网络结果未知后继续使用原 key；充值后让用户再次点击生成并复用请求，不自动重提。修改模板/质量/图片意味着新请求，不能污染已经提交的幂等键。
6. 任务数据至少包含 task_id、status、modality、quality、template_id、diamond_cost、estimated_poll_interval_seconds、refunded/refund_amount、错误信息、结果资源和时间。创建成功校验任务身份、质量、媒体种类、非负扣费及合法状态，扣费以服务端 diamond_cost 为准，不在本地扣币或退款。
7. 状态为 processing/succeeded/failed。刷新必须校验任务 ID、模板、媒体种类、质量、扣费不变；终态不回退或相互改写；refunded=true 不退回 false；退款金额必须处于 0 至扣费之间。
8. 错误映射基线：402/400101→余额不足；409→请求冲突；400→图片不合法；401/403→会话错误；503→不可用；其他→未知。只有明确余额不足触发购买入口。HTTP 错误体有已知业务 code 时优先识别它。
9. 收到受理结果后保护必要落盘，发布前检查 epoch；切换账号不能把旧任务发布到新账号。互斥处理同一记录的提交、查询和首页通知确认，避免相互覆盖。
10. 首页终态通知的确认按账号与请求持久保存；重复点击只认第一次。processing 点击不确认隐藏；成功/失败已查看后不再提示，但保留任务和退款查询。
11. 作品返回校验分页、ID、task_id、modality、MIME、URL、有限非负时长与非负尺寸；0 尺寸可加载，但不凭空填尺寸。只查询 generated 资源，不能把原始上传当作完成作品。
12. 宿主提供跨页面共享的调度器：前台/有效会话轮询本机已知 processing 任务，以及 failed 且已扣费但未退款任务；服务端建议间隔受本地最小/最大值约束。任务变化后刷新作品、余额和流水；离开生成页不丢任务，后台停止主动轮询，重新前台恢复。首页与“我的”使用同一状态源。

边界：基线没有查询全部历史任务列表的接口，本机索引丢失或换设备后，不能承诺找回所有未完成任务；成功作品由资源接口读取。Core 有查询与间隔配置，持续轮询/列表合并是宿主责任，不因创建 Repository 就宣称完整闭环已接好。

| GET wallet/transactions | page/page_size；transactions/total/page/page_size |
| POST orders | 必传 product_id、trigger、platform=android；返回 order_id、product_id、status |

- WalletSnapshot 包含 epoch、可空余额、商品、流水、nextPage/hasMore。未知余额不假定为零。余额查询与流水查询各自串行，异步发布核对 epoch；余额响应 user_id 必须匹配当前用户。
- 金币展示继续使用接口 diamond 数值，不做比例换算。商品必须类型匹配且非订阅，按 ID 去重；建单结果非空且商品匹配。platform 不能因序列化默认值省略。
- 商品字段包括 id/type/name/price/currency/value/bonus_value/google_product_id/third_party_product_id/is_subscription/first_buy_price/first_buy_bonus_value/is_first_buy_promotion/original_price。
- 复刻基线显示规则：币数取 value；首购价取 first_buy_price，缺失回退 original_price；普通价取 original_price；首购赠币取 first_buy_bonus_value，否则 bonus_value。缺币数或显示价不能假装可正常展示。Play ID 为 google_product_id，null 时回退 third_party_product_id。实际 Play 结算使用查询到的商店商品，不把展示价格作为 SDK 付款参数。
- 流水刷新从第 1 页重置，加载更多合并并按 ID 去重；校验 page/page_size/total，空页停止继续加载。
- 充值通知使用 WebSocket `<stream前缀>/connection/websocket`，连接帧为 `{id:1,connect:{data:{token:<当前token>}}}`。处理心跳、首帧与空闲超时、断开及有上限的指数重连；前台或会话变化重建/关闭连接。
- 解析顶层 pub 或 push.pub 的 data，仅接收 message_type=notification、content 内 notification_type/type=recharge 的通知。基线要求 title/body 非空；去重键依次取 notification_id、data.order_id/orderId、类型/标题/正文/时间组合。若新通知不含这些字段，按新契约修改解析器，不能静默漏通知。
- 通知带 epoch、独立去重 key 和可空 orderId。通知唤醒真实余额/流水/商品刷新与支付路由，不直接按通知文本加币。短时间流去重不能代替交易成功的持久去重。

### 9. Google Play Billing

- 实现 BillingManager/Repository、连接状态、商品与购买模型、购买准入、回调关联、pending 注册表、消费协调器。正式金币入口只使用 IN_APP 消耗型商品；底层即使保留 SUBS/acknowledge 模型，也不因此开发订阅业务。
- 进程级准入必须在初始化、查询商品、建单之前取得；重复点击不排队变成第二次购买，任意异常都释放准入。业务订单与 Play 平台订单分别命名，不能混淆。
- LEGACY 顺序：连接 Billing → 查询指定 Play 商品 → 创建业务订单并持久登记归属 → 拉起 Play → 等待购买回调 → PURCHASED 才消费。SERVICE 官方分支使用已经建好的订单，绝不再次建单。
- 拉起 SDK 传当前用户关联和业务订单关联；基线分别使用 obfuscatedAccountId 与 obfuscatedProfileId。与服务端核对关联语义后再做变换，不自行哈希或替换导致回调无法找单。
- 活跃购买按 SKU 与业务订单匹配全局回调；已结束请求的迟到回调不能完成下一次购买。持久记录 productId、orderId、productType、purchaseToken、userId；恢复匹配优先 token，其次 order，只有唯一候选时才用 SKU。
- PENDING 只保留待处理，不消费、不显示到账；取消单独返回；失败携带阶段（初始化、商品查询、建单、购买、消费）。Core 中 COMPLETED 表示消费流程完成，不能当作服务端发币。
- 相同 token 的消费并发合并，成功后清理待处理记录；消费失败可以重试；调用页面取消不取消已启动的必要消费。重复回调再次写入已消费 token 时也要收敛记录。
- 前台连接后查询历史 PURCHASED，仅自动处理本地跟踪的交易，保留原账号归属。处理旧账号交易后不能刷新/通知为当前账号到账。消费后读取真实余额和流水，失败保留最后一次服务端数据。
- 基线没有独立客户端 HTTP 验单接口，不能新增一个臆测的 verify 路径。若目标后端需要上传 purchaseToken/验单，先取得契约，再放到正确环节，并独立测试服务端确认结果。

### 10. 双支付流程与第三方状态机

统一 PurchaseRouter 负责新购买、恢复官方支付和充值通知分派。新购买由外置 LEGACY/SERVICE 选择，失败不能自动跨流程兜底。历史 LEGACY 订单与 SERVICE 订单分别持久记录并按原流程恢复；切换配置不迁移历史订单。

SERVICE 顺序：先持久记录 CREATING → 业务建单 → 保存 orderId/INITIALIZING → 支付服务 initialize → 官方 SDK 或第三方收银台。

| 支付 API（相对独立支付基址） | 契约 |
| --- | --- |
| POST client/payments/initialize | 原业务字段仅order_id；重构时另含按第2.1节生成的前缀冗余字段，不新增其他业务参数 |
| GET client/payments/{编码后的orderId}/status | 校验返回 order_id 与请求一致 |
| POST client/payments/{编码后的orderId}/client-events | 可选遥测，不决定交易结果 |

支付成功响应使用 `{data,code?}`；code 缺失或为 0 且 data 有效才接受。保留 HTTP 状态和有限的技术错误分类供调试，不直接展示服务端原文。

初始化结果必须校验：

- order_id 一致且非空，channel_code 非空；未知 channel_type 拒绝。
- official：channel_code=google_play、open_mode=sdk、sdk_params.product_id 非空。官方 SKU 使用该字段，不能回退商品列表 SKU。
- third_party：open_mode 为 webview/external_browser；payment_url 是有 host、无用户信息的 HTTPS URL；expires_at 为可解析的带时区时间。期限与查询频率使用服务端有效值并受本地上限约束。

状态与恢复规则：

| 状态/情况 | 必须保持的行为 |
| --- | --- |
| CREATING 后建单超时、没有 orderId | 记 UNCERTAIN；同商品再次点击不能自动重建；等待后端提供安全找回/幂等契约 |
| INITIALIZING 遇到 401/503/初始化处理中409/网络未知 | 保留原订单，用户重试复用它，不新建或换渠道 |
| 初始化403 | 本地 ACCESS_DENIED，保留记录并停止恢复该订单；只在用户下一次主动购买时可建新单 |
| 初始化404或409 PAYMENT_ORDER_NOT_INITIALIZABLE | 按明确不可初始化处理；不能把所有409合并为终态 |
| OFFICIAL_READY | 先原子领取并落盘 OFFICIAL_LAUNCHED，再调用 SDK；重启后不能自动弹起支付 |
| 官方消费完成 | OFFICIAL_CONSUMED；释放新购限制，仍等待可关联的真实到账通知，不本地加币 |
| CHECKOUT/VERIFYING | 串行处理打开、轮询、关闭、通知与成功确认，避免竞态重复成功 |
| status=paid 且 fulfillment_status=fulfilled | 第三方唯一成功判据，保存 SUCCESS，再刷新钱包与通知 UI |
| paid 但未 fulfilled | AWAITING_FULFILLMENT，不能报成功或要求重新付款 |
| pending / 未知状态 / 查单失败 | 继续等待或 UNCERTAIN；未知结果不是交易失败 |
| 服务端 failed/cancelled/expired | 明确失败终态，停止付款等待 |
| 用户关闭 | 有界串行查单；如成功处理成功，否则关闭 UI 并保留未决记录；CLOSED 不代表服务端取消 |
| 本地超时/时钟回拨 | TIMED_OUT，保留未决记录；不能重置截止时间扩大付款窗口 |
| 后台/重新前台 | 后台暂停周期查询；重新前台核对，关闭/超时单只补核对而不无限重启周期 |
| SUCCESS | 持久 successShownAt/successAcknowledged；恢复剩余提示时间，确认后不重放 |

PaymentRecord 至少包含本地 key、userId、productId、source、orderId、初始化结果、stage、openedAt/deadline、successShownAt/successAcknowledged、内部 error。订单记录与会话凭据分开，不在支付记录重复存 JWT。存储读取/落盘失败时不能继续付款动作并假装记录可恢复。

补充约束：

- 恢复旧版本时，仅把“INITIALIZING、无初始化结果、有 orderId、error=payment_order_forbidden”的记录迁移为 ACCESS_DENIED；不要误迁移其他未决订单。
- 恢复订单不自动重开 WebView/浏览器；旧 source 不重放失效导航。其他订单到账不能关闭当前收银台，成功提示可排到当前操作结束后。
- 同账号、同商品存在未决订单时优先恢复。所有操作和回调检查 epoch/userId，跨账号只能保留记录，不能展示给新账号。
- LEGACY 记录 orderId/userId/notified，第一次通知与重复通知分别处理。SERVICE 第三方收到充值通知仍查 status；缺 orderId 或归属无法确认时只刷新/核对，不能走旧提示绕过 fulfilled 条件。SERVICE 官方沿用匹配订单的真实通知确认，不擅自套第三方状态查询契约。
- 每次实际支付失败只产生一次当次事件；历史恢复不重放。UI 将事件映射为资源文案 `Something went wrong. Please try again later.`；取消、pending、待发币、查询未知不作为支付失败提示。
- client-events 使用独立持久队列，包含协议内事件类型、渠道、打开方式、时间和错误码，不采集 URL/HTML/表单。队列限制长度与次数；已确认不可重试的 400/401/403/404/413 丢弃，其余有界重试；按账号发送，失败不影响交易。重复事件不能宣称服务端已保证严格幂等。

### 11. 宿主必须接入的部分

交付可编译的最小宿主示例或现有宿主的接入改动，并说明调用顺序：

1. Hilt提供所有配置、SessionStorage、归因source/storage/provider、profile/补报API、EventTracker与BackendAnalyticsSink、模板/生成/上传资源仓库、支付存储与Repository/OrderFactory/EventSink/Clock及UserDataCleaner。确保没有业务依赖提前创建绕过地区准入。
2. Application不提前初始化业务SDK；Splash首帧后先按变体完成RegionAccess，随后RESUMED Activity绑定AppsFlyer，AnalyticsHub初始化，AnonymousStartup认证/profile后进首页。A/B均无登录选择；观察当前epoch的ProfileMode，迟到刷新可更新布局。
3. 前台调用 Billing 恢复、RechargeNotifications.setForeground(true)、PaymentCoordinator.foreground(true)、生成共享调度；后台关闭对应调度。观察会话切换清空展示状态与旧订阅。
4. 原生选图交给图片存储准备；生成 ViewModel 管草稿、质量和失败重试；共享任务调度器服务首页/我的/任务详情。
5. 商品卡和主按钮调用同一个 PurchaseRouter；Activity 有效时才能拉起 Play。不要在 ViewModel 长期保存 Activity。
6. WebView/外部浏览器按服务端 open_mode 打开。WebView 开 JavaScript、禁文件/内容访问与混合内容、SSL 错误不放行、不附加业务 Bearer；仅接受已校验链接。支付 App scheme/跳转域待契约，不能放行任意 intent。外部浏览器只能观测打开/返回，不能伪造 page_loaded 或主动关闭事件。
7. 充值通知先校验 epoch，再交支付路由判断归属；成功由共享状态驱动提示、刷新和必要导航。支付页返回、consume 或余额局部变化均不能单独伪造第三方成功。
8. 正式页面不提供退出/注销；保留的底层清理扩展仍需隔离用户图片/任务/钱包/媒体缓存与安装归因/安装ID/未决支付归属。设置保留正式隐私/条款/Contact/About，删除FAQ。

前置地区策略由独立RegionAccess及LocalRegionSource/IpRegionSource/RegionNetworkSource实现：每次检查，无放行缓存；本地SIM或系统地区命中直接拒绝，否则要求有效允许的IP国家码。联网前后检查、离线不消耗重试，网络存在时查询异常额外重试5次；禁止携带业务标识或共享业务日志。宿主将受限/离线/查询未知映射到友好文案与诊断码，不展示原始地区/IP/异常。复用到其他产品时按实际地域服务要求外置配置，不能把地区逻辑与归因类别混合。

不实现完整品牌 UI、聊天、订阅、个人资料/头像服务、通用文件上传服务、数据库同步或后台常驻精确轮询。这些不是本功能包的已实现基线；需要时另定范围和契约。

### 12. 开发顺序、验收与交付

按“配置/网络/会话/地区准入 → SDK适配与归因 → 匿名启动/profile/补报 → EventTracker与四端分发 → 钱包/目录/生成 → Billing/双支付埋点 → 宿主集成”实施。可以独立验证的部分先交付；不把后端未提供的契约补成假实现。

至少覆盖以下有业务意义的自动测试；API、存储、时钟、SDK 用可控替身，不调用真实支付来跑单元测试：

| 范围 | 必测场景 |
| --- | --- |
| Model扩展 | 所有自有模型1–5字段/确认前缀；编码默认值；旧响应/记录兼容；同请求重试稳定；equals/hash/copy/StateFlow语义；无敏感拼接；手写传输路径核对 |

| 会话/网络 | 并发401只刷新一次；刷新后最多重试一次；同账号重新登录隔离旧请求；旧revision不能清新token；存储失败不发布；支付401不误踢主会话 |
| 归因/登录 | SDK请求接受不等于归因成功；Activity附着/解绑/后台等待/重试合并；5秒放行与10次有限重试；缓存竞态；嵌套类型；profile缺失/旧epoch；补报成功后再刷新、不重登 |

| 目录 | HOME=true、VIDEO=false、IMAGE不传；分页/筛选/重试保持；异常元数据；0/缺失/负报价；真实失败不回退fixture |
| 生成 | 有效图片、空文件、超限/取消；同key重试只受理同一请求；冲突/余额不足；受理落盘；终态与退款不回退；旧账号结果隔离；已查看通知重启不重现；0尺寸作品 |
| Billing | 查询成功才建单；重复购买准入；pending不消费；错误SKU/旧订单回调；同token消费合并、失败重试与取消；恢复仅处理已跟踪交易 |

| 查单/恢复 | paid未fulfilled不成功；关闭/超时/前后台/重启/时钟回拨；账号切换；其他单到账；消费不冒充发币；不重放旧导航；成功确认持久化 |
| 流程/事件 | 切换只影响新购；无失败兜底；历史订单通知归属；失败事件不重放；事件队列有界、隔离、失败不改交易；日志开关/脱敏不改报文 |

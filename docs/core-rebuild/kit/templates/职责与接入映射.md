# 职责与接入映射

本表与reference源码、contracts公共API清单共同使用。新项目确认参数后填写实际新类和方法；下列目标职责是可调整建议，不预先替开发者确定包名。template宿主是验证依赖与启动的样例，不是已经完成的目标项目。

| 原包/主要类 | 目标职责建议 | 公共入口与宿主责任 | 随包验证来源 |
| --- | --- | --- | --- |
| config / CoreRuntimeConfig、ClientIdentity、AppConfiguration | environment、identity、account-policy | Gradle→BuildConfig→ConfigurationModule，Core只收类型化配置；namespace可改，dev服务身份不改 | 配置校验、APK指纹与证书 |
| network / NetworkModule、AuthApi、SessionAuthenticator | transport、auth-protocol、credential-refresh | 公共与受保护client隔离，401合并刷新，epoch/revision防旧请求污染 | Core网络/会话测试 |
| auth / SessionCoordinator、AuthRepository、AnonymousStartup、UserProfileRepository | session、authentication、startup-profile | startup.start，profile.state；每次真实匿名认证，首次profile成功才路由；清理不清安装归因 | AnonymousStartup与Session等测试 |
| region / RegionAccess、CountryIsRegionSource | admission-policy、region-source | check在业务Lazy.get之前，宿主提供SIM/系统区域与联网判断 | RegionAccess测试；原RegionGateViewModel供完整错误/Exit界面参考 |
| attribution / AttributionCoordinator、AttributionReports | install-attribution、attribution-delivery | 等待有效RESUMED Activity、失败/5秒放行、迟到补报后刷新profile；请求成功不等于归因成功 | Core归因测试、AppsFlyer前台启动测试 |
| analytics / EventTracker、BackendAnalyticsSink | event-contract、backend-events | app BusinessEventQueue、AnalyticsHub负责分发；Firebase由宿主提供，另两SDK来自integration；s_/a_/z_/f_互不替代 | 埋点及队列测试；真实四端收数需平台联调 |
| catalog / ApiTemplateRepository | content-catalog | load(channel,categoryId,page)，首页视频home_featured=true，视频tab=false，图片不传；页面分页/Retry保持条件 | ApiTemplateRepository及fixture测试 |
| visual / UploadedPhotoRepository、PrivateGenerationStorage | upload-library、local-image | photos；prepare(Uri)、prepareRemote等以原API为准；只选图时不创建付费任务 | 图片/上传资源Core测试；UploadedPhotosSheet与ViewModel作为原生选图参考 |
| visual / GenerationRequestRepository、VisualLibraryRepository | generation-submission、generation-observation | submit/pending/refresh，resources；幂等键持久复用；共享任务轮询、终态与退款策略见GenerationViewModel及VisualLibraryViewModel | 生成/恢复/库测试；真实生成验收另做 |
| wallet / WalletRepository、RechargeNotifications | wallet-query、recharge-notifications | refreshBalance/refreshProducts/transactions、setForeground；余额真实刷新，WS通知按订单归属交给PurchaseRouter | 钱包与通知测试 |
| billing / BillingManager、BillingRepository、CoinPurchaseController | play-adapter、consumable-orchestration | Activity启动购买；前台恢复与pending消费；消费完成不冒充余额到账 | Billing与消费编排测试 |
| payment / PurchaseRouter、LegacyPaymentFlow、ServicePaymentFlow | checkout-routing、legacy-order、service-order | buy/launchOfficial/recharge；LEGACY/SERVICE新单分流，历史订单固定原流程 | 两流程与订单状态测试 |
| payment / PaymentCoordinator、PaymentEngine、PaymentEventQueue | checkout-state、checkout-telemetry | foreground、state、failureEvents；paid+fulfilled才成功，浏览器关闭/超时不是取消 | 支付状态/遥测/恢复测试；PaymentScreen是WebView和外部浏览器桥接参考 |

## 最小宿主与目标宿主的区别

已装配宿主绑定完整Core、AppsFlyer和数数依赖，初始化Firebase并接四端Hub，真实启动/profile和只读钱包按钮用于手动冒烟。HarnessRuntime中的Core入口可被调试器或新宿主调用；不会在自动构建时联网执行业务。

目标项目必须实现：原生选图、目录/生成/作品页面与共享轮询、余额/购买页、Activity支付启动、SERVICE网页桥接、失败单次提示、真实资源状态。reference/app包含业务ViewModel与必要系统桥接，品牌Compose组件/主题未整体复制，原页面文件仅供行为参考，不直接加入最小宿主编译。按完整提示词完成页面职责才算功能包在目标项目完成接入。

Android/Play/Firebase的运行期行为不能由JVM测试证明。未经真实设备和平台确认，不将归因收数、支付、退款、生成结果标为通过。

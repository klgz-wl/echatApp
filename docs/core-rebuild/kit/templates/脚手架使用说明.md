# Python3 Core脚手架

入口为包根目录下的 `validation/core_scaffold.py`，Python3.9+，仅标准库，无需pip或AI API Key。脚本需要完整材料目录（模板、Core/SDK、配置、工具）；只复制一个.py不能代替配套材料。它负责参数、工程装配、任务生成、构建/部署；AI读取生成的任务完成实际重构，不由Python正则批量改写Kotlin模型。

## 开发者只填写一次参数

在本交付包根目录执行：

```sh
python3 validation/core_scaffold.py configure --output ../scaffold.local.json
python3 validation/core_scaffold.py init --config ../scaffold.local.json --dry-run
python3 validation/core_scaffold.py init --config ../scaffold.local.json
```

问答包含：新建/已有模式、项目名、app/core namespace、Model前缀、存储前缀、宿主模块名、目标目录、私密dev签名目录和SDK目录。前缀无默认值。最后展示摘要，输入yes确认后才写参数文件；签名密码不要求输入。问答中的相对路径按运行目录解释，保存为绝对路径，写入参数文件的_local区，不写入生成的AI提示词或可发布元信息。手工填写JSON时，相对路径按参数文件所在目录解释；CLI的--target/--private-signing/--sdk按运行目录解释，并可覆盖本机路径。

初期全量保留Core，prod显式DEV_REUSE，dev固定yumo.achat.app。公共版本/阈值/协议与联系配置继承已交付基线，品牌和正式资料后续单独确认；项目名、namespace、存储名自动调整。该初始化不会把Vexora实际prod身份复制为新项目prod。已有Google/账号底层接口仍保留，真实入口匿名规则见完整提示词。

生成后，开发者把目标项目中的 `docs/core-rebuild/开始重构.md` 交给AI。文件已携带确认参数、步骤、Model规则、完整本地参考材料和验收命令；AI直接实施，只补问新增冲突或未知项。无需再次提供同一前缀或重复抄写dev SDK参数。无需原工程或历史对话。两种模式均在根AGENTS.md及任务提示词写入每次任务完成后中文git commit和git push的规则，明确精确暂存、验证、upstream/origin、无远程和失败处理；已有AGENTS.md保留原文追加，脚本初始化本身不代替AI提交推送。

## 两种模式

**new：新工程。** 目标必须不存在、为空，或仅包含有效的.git目录/工作树标记；保留已有Git元数据、当前分支和远程，不重新git init。生成Gradle Wrapper、独立core、两个integration模块、可编译最小宿主、DI/归因/四端统计生命周期、dev及临时prod、签名模板、Model台账和本地提示词。namespace包声明/import/源码目录/混淆规则、宿主模块名、测试资源路径与配置同步迁移。存在.git之外的原文件则拒绝覆盖；发布失败撤回本次文件，保留原Git仓库。

**existing：已有工程。** 目标须含settings.gradle(.kts)。脚本只新增 `.core-scaffold/prepared` 的独立完整基线和 `docs/core-rebuild` 接入资料、状态文件，并追加.gitignore和AGENTS.md任务规则；现有Gradle/页面/导航/业务文件原样保留。生成的AI任务包含当前构建文件哈希和语义合并清单，要求AI适配依赖版本、模块/源码、DI、生命周期、配置、资源、SDK和业务调用点，处理旧core后再移除被替代源码。最终在真实目标工程验证，不能只验证prepared。

自动构建验证协议为Kotlin DSL、独立core、integration:analytics-appsflyer/analytics-thinkingdata、environment维度dev/prod与Debug/Release；宿主模块可自定义。existing能为Groovy项目生成迁移任务，后续AI需明确DSL/构建矩阵映射再接入验证，脚本不会声称能无损自动合并任意Gradle脚本。扩展其他模块时需同步部署输入范围和验收任务。

签名若未在初始化时提供，之后运行：

```sh
python3 validation/core_scaffold.py signing --project TARGET --private-signing PRIVATE_DEV_SIGNING
```

已有工程完成AI合并后可从prepared中取私密签名，或仍用原附件执行上述命令。不同证书拒绝覆盖。sharedDev私密文件不进Git、部署包或APK。

## 分阶段验证

JDK17可由JAVA_HOME指定，SDK由ANDROID_HOME/ANDROID_SDK_ROOT或local.properties提供。命令仍从本材料包根运行，TARGET为真实目标工程：

```sh
python3 validation/core_scaffold.py doctor --project TARGET
python3 validation/core_scaffold.py verify --project TARGET
python3 validation/core_scaffold.py verify --project TARGET --refactored
```

doctor检查模板接入文件、namespace、固定dev配置/Firebase/地址、证书文件和SDK。verify运行Core/AppsFlyer/宿主单元测试、devDebug/devRelease、Lint及临时prodDebug，检查实际APK包名、证书、配置指纹、Google资源、Manifest、release属性和私密材料。日志在.core-scaffold/verify.log，不打印SDK值或密码到提示词。脚本不安装应用、不调用真实平台、不购买或生成。

--refactored另外校验全量Model计划、目标实现文件和审查说明，拒绝初始化空台账。Model计划在 `docs/core-rebuild/model-plan.json`，schema=2的models按实际目标逐项登记target_file和extension_files，baseline_mapping覆盖所有基线去向并支持拆分/合并；旧schema=1一对一格式仍兼容。完整JSON示例见Model审查与改造方法。字段/序列化名必须在指定实现文件出现；此检查是存在性检查，不能替代serializer/equals/copy等语义测试或代码review。`refactor-review.md`记录结构/API映射、宿主完整接入、逐模型验证及未验收平台项。

通过报告记录输入哈希；变更源码/配置/相关文档后旧结果失效，必须重新验证。BASELINE_PENDING_REFACTOR/EXISTING_PENDING_INTEGRATION是初始化来源标记，实际是否完成重构以当前--refactored报告和review为准。

## 将已重构结果部署到其他目标

```sh
python3 validation/core_scaffold.py pack --project TARGET --output ../refactored-core-bundle
python3 validation/core_scaffold.py deploy --bundle ../refactored-core-bundle --target DESTINATION --plan ../deploy-plan.json
python3 validation/core_scaffold.py deploy --bundle ../refactored-core-bundle --target DESTINATION --plan ../deploy-plan.json --apply
```

pack要求当前源码已经通过verify --refactored；普通基线或旧验证记录不能打成“已重构包”。部署包包含配置/宿主接入/Gradle/源码/参考说明，排除构建缓存和签名秘密。pack限定既有app/core/integration/gradle/config及接入文档范围；不声称自动识别任意自定义模块依赖。

首次deploy只生成包含每个文件旧/新哈希及创建/覆盖/删除的计划，不写目标。review计划后--apply绑定同一包和同一目标快照，期间任一相关文件改变则拒绝执行，必须重新生成计划。已有工程语义合并应先由AI完成；deploy是传递已验证文件集，不是任意项目的自动合并器。目标无关文件保留，.gitignore合并保留原规则，并将本机状态及签名忽略规则置于末尾，避免已有反向规则抵消保护；只清理此前由脚手架管理且已被新包移除的文件。

应用前备份到.core-scaffold/transactions/事务ID；单进程锁防并发，失败自动恢复。回滚前先核验全部备份及部署清单完整性，部署后的文件内容或执行权限已被手工修改时拒绝覆盖；备份损坏时也不写入目标。保留事务以便追溯，不自动删除备份。回滚命令：

```sh
python3 validation/core_scaffold.py rollback --project DESTINATION --transaction TRANSACTION_ID
```

部署后在目标装配签名、配置本机SDK，再运行verify --refactored。来源工程通过不代表另一个目标的宿主合并和设备业务已经通过。自动校验只检查受信任的本地构建结果和哈希，不是第三方安全签名或平台认证；不要执行来源不可信的Gradle工程。

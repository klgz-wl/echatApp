# AppsFlyer 归因与启动模式

更新：2026-09-17。用户最终确认所有正式入口只使用匿名登录；取消 A 面登录页面，以及“我的”和设置中的退出登录、删除账号菜单。旧的 A 面三种登录、缓存决定兜底页面和 8 秒等待规则已失效。

## 启动与缓存

1. 系统 Splash 后立即呈现应用 Splash：透明 Figma Logo 居中按 128×128 显示、底部旋转 loading（不另显应用名）。首帧显示后初始化统计 SDK，不再用系统 Splash 的保持条件阻塞首帧。没有独立指定的新 Splash Figma frame，沿用已核验 Logo。
2. AppsFlyer 等待有效安装归因；失败、未知状态或 5 秒没有结果仅放行登录，不决定 A/B。历史缓存只保留真实归因数据。原 Organic=A、Non-organic=B 和失败兜底 A 的规则已取消。
3. A/B 均调用真实 `auth/anonymous`，成功建立会话后请求 `GET /api/v1/user/profile`，读取必需布尔字段 `is_new`：true 显示 B，否则显示 A；请求完成后进入首页。旧会话不能绕过本次匿名认证。正式导航不展示 Google、账号密码或 Guest 选择环节。
4. 无网时不继续认证，Toast 友好提示，Splash 底部 loading 改为 Retry；匿名接口失败、profile 请求失败／is_new 缺失或总启动超时同样留在 Splash，点击重试。配置集中于 `config/app.properties`：ATTRIBUTION_TIMEOUT_MS=5000、STARTUP_TIMEOUT_MS=30000。
5. 归因失败或超时后，由进程级协调器每隔 ATTRIBUTION_RETRY_INTERVAL_MS=5000 毫秒尝试 SDK 归因，最多 ATTRIBUTION_RETRY_ATTEMPTS=10 次；有效结果到达即停止。任务与页面生命周期无关。
6. 迟到有效回调更新内存、持久缓存和后续登录参数，并使用参考工程 `POST attribution/report` 补报真实结果。补报成功后再次获取 profile，按最新 is_new 更新共享模式，页面保留当前导航位置。资料刷新与启动首次读取串行，并按 session epoch 隔离；失败保留最近一次真实模式，在归因补报的有限重试内重试，不重新登录。
7. 归因缓存读写与路由等待分离，磁盘异常不阻塞 5 秒兜底。不伪造 Organic、活动名称、安装时间；无历史数据也无回调时 extra_data 保持空对象。安装归因独立于用户会话。
8. `DESIGN_PREVIEW_MODE` 只用于 Debug 设计预览，与 dev/prod 独立；旧 APP_MODE 不参与正式路由。底层历史登录、退出接口保留为能力，正式页面没有这些入口。

SDK 回调语义参照 [AppsFlyer Android conversion data](https://dev.appsflyer.com/hc/docs/conversion-data-android)。模拟器与自动验证见 本次验证记录（历史参考，契约以本文正文和随包源码为准）。

## 登录请求字段

`auth/google`、`auth/anonymous`、`auth/login` 的 JSON body 均增加非空 `attribution` 对象，统一由 AttributionCoordinator 构造。参考工程实际端点名为 `attribution/report`，用户写的 `attribute/report` 在此作为同一归因格式的指代；迟到有效回调通过该真实端点独立补报，不重新登录。

| 字段 | 来源 |
| --- | --- |
| attribution_source | `appsflyer`，沿用户指定值 |
| device_id | Android 广告 ID 可用且未限制追踪时使用 GAID；不可用、尚未取得或限制追踪时沿用参考工程的本地持久设备 UUID |
| af_uid | `getAppsFlyerUID`；有效回调缓存同时保留该值 |
| network | media_source，兼容 network |
| campaign / campaign_id | campaign；campaign_id，兼容 af_c_id |
| adgroup / adgroup_id | af_adset / af_adset_id，兼容同名通用字段 |
| creative / creative_id | af_ad / af_ad_id，兼容同名通用字段 |
| channel | af_channel，兼容 channel |
| country | country_code，兼容 country；不把系统语言猜成实际国家 |
| platform | android，不复制 iOS 示例值 |
| app_version / package_name | 当前构建的 VERSION_NAME / APPLICATION_ID |
| extra_data | AppsFlyer 原始回调 JSON，补 af_uid；保留布尔、数字、嵌套对象、数组和 null |

登录 body 原有 device_id 仍为稳定设备 UUID，不改变参考认证绑定规则；归因子对象的 GAID 是独立标识。GAID 查询在后台线程，不阻塞主线程；不可用时不读取其他系统硬件标识。字段缺失不填示例中的 Facebook／Meta／US 等固定值。

2026-09-16 修正缓存读取竞态：登录快照前对正常缓存加载增加有界等待，外置 `ATTRIBUTION_CACHE_WAIT_MS=200`；超时继续使用当前内存数据，缓存读写卡住仍不阻塞归因路由。登录请求只快照本次实际可用归因；已发出的请求不会被迟到回调重发。归因缓存写入 DataStore，原子保存；缓存异常仍可使用内存中的真实回调。归因日志只输出有效状态；HTTP 日志遵循 dev/prod 独立脱敏配置。

## 验证边界

核心测试覆盖 Organic／Non-organic、等待、失败／超时、缓存、迟到回调、并发决策，以及三种登录均携带归因并保留原认证设备身份；序列化检查字段名和 extra_data 类型。实际设备和构建结果见 归因验证记录（历史参考，契约以本文正文和随包源码为准）。没有通过人工灌入广告数据来声称真实投放归因成功。

2026-09-17 新增 profile true／false、首次请求失败重试、补报后刷新、串行读取及账号切换隔离测试；当前执行结果见 本次验证（历史参考，契约以本文正文和随包源码为准）。历史归因测试记录不代表新的 profile 选面已完成线上验收。

prodRelease 的地区检查位于匿名启动之前，拦截或 IP 未知均不进入认证、不产生 silent_login 失败事件；地区规则及安全窗口见 发布保护说明（历史参考，契约以本文正文和随包源码为准）。

## 2026-09-18 延迟归因启动修复

已修复“Activity 首帧后仍用 Application Context 调用 start”的接入问题。地区放行后仅绑定当前 RESUMED 的 Activity，首次及重试使用该 Activity 调用 AppsFlyer start；后台等待下次前台，不回退 Application Context，单例不强持有 Activity。init 与 GAID 查询也不能越过地区检查。请求接受／失败的诊断状态与实际归因回调分开，补入 Google Play Install Referrer 2.2。旧包证据及详细验证见 AppsFlyer 归因测试排查（历史参考，契约以本文正文和随包源码为准）。真实平台归因仍待同事复测。


2026-09-18 AppsFlyer 兼容性更新：官方已将参考工程沿用的 6.12.2 列为 End-of-Support，安装／会话／事件请求会返回 400（除官方特批例外）。Vexora 升级至受支持的 6.18.1，参考工程保持只读；dev/prod 包名、Dev Key、地区前置门禁、Activity 延迟启动及支付事件参数不变。新 SDK 的 allowBackup／dataExtractionRules 声明由应用显式覆盖，继续禁止备份与设备迁移。新增外置 APPSFLYER_DIAGNOSTIC_LOGGING，dev 开启、默认及 prod 关闭；devRelease 仅输出白名单启动阶段、数字错误码及回调有效性，不输出凭据、标识、原始错误或事件载荷，完整 SDK／HTTP 日志仍只在 Debug 开启。排查与验证详见 docs/AppsFlyer归因测试排查.md 第 8 节。

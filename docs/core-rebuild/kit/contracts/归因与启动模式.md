# AppsFlyer 归因与启动模式

更新：2026-10-30。启动先恢复已有会话；无法恢复时显示登录选择页。用户可主动一键匿名登录或使用账号密码注册即登录；“我的”页面提供退出和注销。历史记录不覆盖这些规则。

## 启动与缓存

1. 地区和安全检查、独立公共配置请求继续在 Splash 执行。设备标识首次读取使用并持久化 Android ID；有历史 UUID 且会话有效或可恢复时保持 UUID。
2. 有会话时先读取资料；401 只尝试刷新 token。刷新被服务端确定拒绝后清除会话并显示登录选择页。离线、超时和 5xx 保留会话，显示重试。会话恢复不重新匿名认证，也不重跑完整登录等待。
3. 无会话时显示登录选择页，协议默认选中。打开选择页、账号表单和协议链接都不启动登录归因链。用户通过协议和输入校验后，一键登录调用 `POST auth/anonymous`，账号表单调用 `POST auth/register`。历史 UUID 且无可恢复会话时，仅在主动一键登录前原子切换到 Android ID。
4. 主动提交登录后继续原有认证前归因等待、真实认证、认证后归因等待、首次资料读取和首页归因门禁；沿用外置超时、成功凭据、补报和共享首页延迟。真实资料 `is_new` 决定 A/B 展示，不用它决定设备标识迁移。
5. 迟到有效归因回调保留原归因结果和 report_id，按报告生成时的账号、设备标识补报。归因后资料刷新按 session epoch 隔离；旧账号异步回调不得污染新会话。
6. “我的”页面退出和注销分别调用受保护的 `POST auth/logout`、`POST auth/delete-account`；只有业务成功后清会话并返回登录选择页。注销确认按钮等待 3 秒。失败保留原会话和设备标识。
7. `DESIGN_PREVIEW_MODE` 只用于 Debug 设计预览，与 dev/prod 独立；安装归因独立于用户会话，不能通过退出清空。

SDK 回调语义参照 [AppsFlyer Android conversion data](https://dev.appsflyer.com/hc/docs/conversion-data-android)。模拟器与自动验证见 本次验证记录（历史参考，契约以本文正文和随包源码为准）。

## 登录请求字段

`auth/google`、`auth/anonymous`、`auth/register` 的 JSON body 均保留非空 `attribution` 对象。运行中的匿名登录由手写 host 路径构造，Core/Hilt 的三种登录由 AttributionCoordinator 构造。参考工程实际端点名为 `attribution/report`，用户写的 `attribute/report` 在此作为同一归因格式的指代；迟到有效回调通过该真实端点独立补报，不重新登录。

| 字段 | 来源 |
| --- | --- |
| attribution_source | `appsflyer`，沿用户指定值 |
| device_id | Android 广告 ID 可用且未限制追踪时使用 GAID；否则使用统一业务设备标识（新安装为 Android ID，保留会话的历史用户可为 UUID） |
| gaid | 与登录 body 顶层 `gaid` 来自同一次 Google Play services 查询；不可用时省略 |
| af_uid | `getAppsFlyerUID`；有效回调缓存同时保留该值 |
| network | media_source，兼容 network |
| campaign / campaign_id | campaign；campaign_id，兼容 af_c_id |
| adgroup / adgroup_id | af_adset / af_adset_id，兼容同名通用字段 |
| creative / creative_id | af_ad / af_ad_id，兼容同名通用字段 |
| channel | af_channel，兼容 channel |
| country | country_code，兼容 country；不把系统语言猜成实际国家 |
| platform | android，不复制 iOS 示例值 |
| app_version / package_name | 当前构建的 VERSION_NAME / APPLICATION_ID |
| extra_data | AppsFlyer 原始回调 JSON，补 af_uid；保留布尔、数字、嵌套对象、数组和 null |

登录 body 顶层 `device_id` 使用统一持久化业务设备标识；顶层 `gaid` 与 `attribution.gaid` 完全相同，均不可使用 Android ID 或历史 UUID 冒充。现有归因子对象 `device_id` 保留 GAID 优先、不可用时使用业务设备标识的口径。统一 AdvertisingIdProvider 在 IO 线程用 Google Play services 查询，重叠调用共享进行中的查询并有等待上限；完成后不缓存或落盘 GAID。限制广告跟踪、删除／全零、空值、非法 UUID 或查询失败时，两个 `gaid` 字段均省略，不借用 AF UID、Android ID 或旧值，也不因此重做安装归因。`attribution/report` 的请求顶层同样增加可选 `gaid`，原结果、去重、重试及账号绑定不变。字段缺失不填示例中的 Facebook／Meta／US 等固定值。

2026-09-16 修正缓存读取竞态：登录快照前对正常缓存加载增加有界等待，外置 `ATTRIBUTION_CACHE_WAIT_MS=200`；超时继续使用当前内存数据，缓存读写卡住仍不阻塞归因路由。登录请求只快照本次实际可用归因；已发出的请求不会被迟到回调重发。归因缓存写入 DataStore，原子保存；缓存异常仍可使用内存中的真实回调。归因日志只输出有效状态；HTTP 日志遵循 dev/prod 独立脱敏配置。

## 验证边界

核心测试覆盖 Organic／Non-organic、等待、失败／超时、缓存、迟到回调、并发决策，以及主动登录携带归因、会话恢复不重新认证、设备身份兼容与异步事件归属；序列化检查字段名和 extra_data 类型。实际设备和构建结果见 归因验证记录（历史参考，契约以本文正文和随包源码为准）。没有通过人工灌入广告数据来声称真实投放归因成功。

2026-09-17 新增 profile true／false、首次请求失败重试、补报后刷新、串行读取及账号切换隔离测试；当前执行结果见 本次验证（历史参考，契约以本文正文和随包源码为准）。历史归因测试记录不代表新的 profile 选面已完成线上验收。

prodRelease 的地区检查位于登录选择与主动认证之前，拦截或 IP 未知均不进入认证、不产生登录失败事件；地区规则及安全窗口见 发布保护说明（历史参考，契约以本文正文和随包源码为准）。

## 2026-09-18 延迟归因启动修复

已修复“Activity 首帧后仍用 Application Context 调用 start”的接入问题。地区放行且用户主动登录或恢复旧会话后，才绑定当前 RESUMED 的 Activity；首次及重试使用该 Activity 调用 AppsFlyer start，后台等待下次前台，不回退 Application Context，单例不强持有 Activity。init 与 GAID 查询也不能越过地区检查。请求接受／失败的诊断状态与实际归因回调分开，补入 Google Play Install Referrer 2.2。旧包证据及详细验证见 AppsFlyer 归因测试排查（历史参考，契约以本文正文和随包源码为准）。真实平台归因仍待同事复测。


2026-09-18 AppsFlyer 兼容性更新：官方已将参考工程沿用的 6.12.2 列为 End-of-Support，安装／会话／事件请求会返回 400（除官方特批例外）。Vexora 升级至受支持的 6.18.1，参考工程保持只读；dev/prod 包名、Dev Key、地区前置门禁、Activity 延迟启动及支付事件参数不变。新 SDK 的 allowBackup／dataExtractionRules 声明由应用显式覆盖，继续禁止备份与设备迁移。外置 APPSFLYER_DIAGNOSTIC_LOGGING 的 dev 安全诊断仅输出白名单启动阶段、数字错误码及回调有效性，不输出凭据、标识、原始错误或事件载荷。dev/prod 均关闭完整 AppsFlyer SDK 调试日志，避免在 Debug 构建打印可能含 GAID 的原始载荷；自有 HTTP 调试日志即使关闭一般脱敏，也强制遮盖 GAID。排查与验证详见 docs/AppsFlyer归因测试排查.md 第 8 节。

# Vexora 埋点事件定义

更新日期：2026-10-26。本文件描述当前代码口径；“已接入”表示存在真实触发路径，不表示自有后端和三个 SDK 平台均已完成收数验收。当前 Zorv dev/prod 默认支付流程为 SERVICE；LEGACY 事件仅在历史订单恢复或显式配置为 LEGACY 时触发。

## 1. 命名、身份与公共参数

### 平台前缀

| 平台 | 手动事件前缀 | 示例 |
| --- | --- | --- |
| 自有后端 events/report | `z_` | `z_purchase_success` |
| Firebase Analytics | `f_` | `f_purchase_success` |
| AppsFlyer | `a_`（原 `af_`） | `a_purchase_success` |
| 数数 ThinkingData | `s_`（原 `ss_`） | `s_purchase_success` |

手动购买成功业务事件统一为 `purchase_success`。旧 `pay_result`、`payment_custom`、`purchase_custom` 和 `purchase_client*` 均停止发送；投放及后台事件映射需同步检查。SDK 自动事件保持平台原名，不加上述业务前缀；AppsFlyer 协议参数 `af_revenue`、`af_currency` 也不改名。

A/B 均匿名登录。设备标识用于关联安装实例，真实匿名 `user_id` 用于关联服务端账号；不把设备 ID 当成永久用户身份。清除数据／重装可能改变本地标识。三端 SDK 分别设置 userId、customerUserId、数数 login；Crashlytics 同步用户 ID。归因 ID 与业务设备 ID 不混用。

下表由统一分发层添加到每个手动事件，专属参数不能覆盖公共字段：

| 参数 | 类型 | 来源与含义 |
| --- | --- | --- |
| `event_id` | string | 每次入队生成 UUID，用于排查和下游去重 |
| `event_time` | long | 触发时 Unix 毫秒，不是网络送达时间 |
| `session_id` | string | 本次业务前台会话；后台超过阈值后再次进入生成新值 |
| `device_id` | string | SessionStorage 的本地设备标识，读取失败为空，不伪造硬件 ID |
| `user_id` | string | 触发时服务端匿名账号；登录前为空 |
| `app_version` | string | 当前构建版本 |
| `platform` | string | `android` |
| `app_mode` | string | 已确定的 `A`／`B`，决策前为 `unknown` |

SDK 布尔参数统一以 long `1`／`0` 发送；整型保留 long、金额保留 double。缺少真实金额／时长时省略，不填零冒充。手动事件只接收标量，参数名最长 40、字符串值最长 100；Firebase sink 独立执行 25 参数上限，其余三端保留完整规范化参数。支付字段按下文使用 AppsFlyer 官方命名，四端一致；支付 af_success 为字符串 true／false，其他业务布尔参数仍沿用 1／0。错误原因用下文稳定枚举，不发送服务端原文、图片内容、媒体／支付 URL、token、购买凭据或广告归因原始对象到手动埋点。

## 2. 全局与页面

所有手动业务事件统一发送至自有后端和三个 SDK 平台，包括浏览、创作、支付漏斗与第三方支付页面事件；不再支持按事件指定单个平台。四端继续遵守各自的构建开关、初始化条件、地区与隐私门禁。

| 事件标识 | 触发口径 | 专属参数 |
| --- | --- | --- |
| `app_launch` | 正式 MainActivity 冷启动或从后台返回；配置重建不重复 | `is_first_launch`：本地首次运行；`launch_type`：cold／warm |
| `silent_login` | 启动匿名认证流程返回成功或失败；用户 Retry 是新尝试 | `is_success`、`device_model`、`os_version`；失败 `fail_reason=offline/authentication_unavailable` |
| `app_exit` | 应用退至后台达到 `ANALYTICS_BACKGROUND_TIMEOUT_MS`，默认 30 秒 | `session_duration`：会话累计前台毫秒，排除后台等待；`exit_reason=background_timeout` |
| `tab_click` | 点击实际底部导航，包含点击当前 Tab | `tab_name`、`previous_tab`：home／video／image／profile；`is_reselect` |
| `page_view` | 页面进入 RESUMED；返回页面、后台回前台重新曝光，Compose 重组不重复 | `page_name`；购买页另带 `entry_source` |

`page_name` 当前覆盖 splash、home、video、image、profile、purchase、records、generation、uploaded_photos、task、media、settings、web、payment_checkout。网页不发送 URL；通用说明弹窗不单独当作页面。上传选择面板在显示时曝光一次，关闭后再次打开重新曝光。

`app_exit` 是可观测的后台超时事件。Android 杀进程、崩溃或强制停止不保证运行回调；若进程在超时前被杀，本事件可能缺失，不能以它统计准确卸载／关闭人数。应用内浏览与真实认证流程独立，`silent_login` 的失败也可能发生在离线或启动超时阶段。

## 3. 浏览与创作漏斗

| 事件标识 | 触发口径 | 专属参数 |
| --- | --- | --- |
| `template_expose` | 首页／视频／图片列表的卡片与视口相交且页面 RESUMED；同次页面与分类内每模板一次，离屏回来不重复 | `template_id`、`category_id`、`modality`、`source`、`position`（当前列表从 1 开始）、`filter_category_id` |
| `template_click` | 点击卡片进入模板详情 | `template_id`、`category_id`、`modality`、`source`、`filter_category_id` |
| `click_upload_img` | 模板页点击 Upload Photo，打开服务端已上传资源网格 | `template_id`、`category_id`、`modality`、`source` |
| `upload_img_result` | 选图本地处理完成，或生成请求携图提交返回；按 phase 分析，不将两阶段相加作上传次数 | 公共模板三参数、`phase`、`is_success`；详见下文 |
| `click_generate` | 已选图片、报价有效、未在提交时，用户点击 Generate；重试会重新记录点击 | 公共模板三参数、`request_id`、`quality`、`diamond_cost`（报价）、`source` |
| `generate_result` | 首次观察服务端任务 succeeded／failed；图片和视频均覆盖，处理中的轮询不发送 | 公共模板三参数、`request_id`、`task_id`、`quality`、`diamond_cost`（实际任务费用）、`is_success`、`source`；失败 `fail_reason=generation_failed`；可用时 `duration` |

公共模板三参数是 `template_id`、`category_id`（服务端所属分类，未知为空）、`modality=image/video`。`source=home/video/image`，旧草稿可能为 unknown；`filter_category_id` 是列表筛选项，与模板所属分类区分。质量为接口值 fast／quality。

`upload_img_result`：

- `phase=local_prepare`：选本机图、或下载已有上传资源后的私有副本校验。带 `selection_source=device/uploaded_resource`；选择器无法打开时该字段省略。错误为 invalid_image／picker_unavailable。用户取消系统选图不当作失败。
- `phase=task_submit`：点击 Generate 后的 multipart 提交响应。带 `request_id`；受理成功带 `task_id`。失败为 insufficient／conflict／invalid_image／unavailable／unknown／signed_out。unknown 表示结果不确定，不代表服务器未收到文件；受理成功也不等于生成成功。
- 没有独立“图片上传云端成功”回调或上传接口，不伪造独立上传完成事件。

`generate_result.duration` 使用服务端 completed_at 减 started_at（缺少 started_at 时使用 created_at），单位毫秒；时间字段无法解析或倒退则省略，不把视频播放时长当生成耗时。按账号＋task_id 的终态键本地去重；轮询、返回、重启不重复发送同一终态。升级后的本机已完成任务可能在首次观察时补记一次，历史远端资源列表不会逐条补记。

## 4. 支付漏斗与收入口径

| 事件标识 | 触发口径 | 参数 |
| --- | --- | --- |
| `view_store` | 充值页进入前台 | `entry_source` |
| `click_package` | 点击商品卡或购买按钮 | `package_id`、`entry_source`、已知的报价与商品字段 |
| `initiate_pay` | 实际启动 Google Play 或第三方收银台 | 订单、渠道、入口和已知报价字段 |
| `purchase_success` | Play consume 成功，或第三方订单同时为 paid 与 fulfilled | 订单、商品、渠道、入口、用户、状态与有效收入字段 |

四端各收到同一基础事件，最终名称为 `f_purchase_success`、`a_purchase_success`、`s_purchase_success`、`z_purchase_success`。不另发 `af_purchase` 或其他成功同义事件。旧 `pay_result`、`payment_custom`、`purchase_custom`、`purchase_client`、`purchase_client_buy`、`purchase_client_buy_{SKU}` 停止发送。取消、失败、pending、unknown、页面关闭和超时不新增结果替代业务事件；原 UI 错误、日志及支付协议遥测继续保留。

成功事件保留 `status=success`、`af_success=true`、`pay_method`、`payment_flow`、`entry_source`、`package_id`、`af_content_id`、`af_order_id`、`stage`、`self_user_id`、`trigger`、`af_content_type=recharge`，以及可确定的 `af_price`、`af_currency`、`price_source`。Play SKU 与业务商品 ID 分别使用 `af_content_id` 和 `package_id`。入口值包括 `home_balance`、`video_balance`、`image_balance`、`profile_purchase`、`generation`、`main`、`restored`。

仅 `purchase_success` 可携带 `af_revenue`。公共业务队列入队和四端分发前，在参数合并后对其他手动事件移除该字段。Google Play 的收入和价格取购买发起时保存的 `priceAmountMicros / 1_000_000`，币种取原 `priceCurrencyCode`，`price_source=google_play`；恢复沿用原订单快照，不查现价、不换汇。第三方的收入和价格取订单创建时保存的美元 `PaymentRecord.quotePrice`，包含适用的首购报价，`af_currency=USD`、`price_source=catalog_quote`。支付服务未返回实付金额时仍按该订单报价统计，不伪称为服务返回金额。非美元报价不得直接贴 USD 标签。

金额必须有限且非负；明确已知的 0 可上报。缺失、负数、NaN、无穷大、币种或单位不明时仍发真实成功事件，但省略 `af_revenue`。没有历史金额快照时不按现价反推，也不批量补报历史收入。自有后台接口将金额转为字符串，SDK 保留数值；四端业务金额和币种一致。

Play 以 consume 成功为边界；第三方仅 `status=paid` 且 `fulfillment_status=fulfilled` 为边界，paid 待到账不是成功。沿用账号隔离、订单记录、原 `purchase_success` 去重键、持久化和并发限制；当前购买、重复回调、轮询、恢复及重启共用该成功身份。已记录成功的旧订单不会因本次改造重新上报。统计失败不改变支付结果。

示例（第三方订单创建时美元报价 2.99）：

```json
{
  "status": "success",
  "af_success": "true",
  "pay_method": "channel",
  "payment_flow": "SERVICE",
  "price_source": "catalog_quote",
  "af_price": 2.99,
  "af_currency": "USD",
  "af_revenue": 2.99,
  "af_order_id": "example_order",
  "af_content_type": "recharge"
}
```

SDK 自动事件保留平台原名。AppsFlyer 参数 `af_revenue`、`af_currency` 不随事件前缀改名。支付字段命名参考 [AppsFlyer Android 官方定义](https://dev.appsflyer.com/hc/docs/in-app-events-android)；支付协议字段和独立建单、验单、查单接口不变。

## 5. 第三方支付页面事件与服务端遥测

以下事件统一发送四端，表中为不带平台前缀的业务名称；实际发送时分别加 f_／a_／s_／z_：

| 当前事件 | 触发 |
| --- | --- |
| `3rdpayment_link_ok` | 第三方支付链接初始化并校验成功 |
| `3rdpayment_link_error` | 初始化失败或打开前发现链接过期；初始化未完成时可能尚未知渠道 |
| `3rdpayment_page_loaded` | 内嵌 WebView 主页面完成加载；外部浏览器无法确认网页加载，不伪造此事件 |

专属参数：package_id、entry_source、af_order_id、channel_code、open_mode、payment_flow=SERVICE、page_name=recharge_paywall；存在打开时间时附 duration（毫秒），有明确错误时附 fail_reason。

独立的 `POST client/payments/{orderId}/client-events` 保持服务端协议名称，不加 f_／a_／s_／z_：link_ok、link_error、page_opened、page_loaded、page_load_error、paid_while_open、paid_on_close、user_cancel、poll_timeout、timeout_cancel。请求包含 event_type、channel_code、open_mode、page、occurred_at、opened_at、closed_at、duration_ms、error_code；可空字段按真实状态填，metadata 当前不填。

该服务端队列持久化、按账号隔离，最多 100 条、每条最多尝试 3 次、间隔 5 秒；400／401／403／404／413 等不可重试响应停止重试。客户端关闭／超时事件不代表后台交易取消。

## 6. SDK 自动采集与自动发送（按平台区分）

自动事件、预置参数和上报批次由 SDK／平台控制，不经过业务前缀函数，也不自动拥有本文件全部公共参数；不能仅因开关打开就声明后台已收到。手动事件在调用 SDK 后也由各 SDK 管理缓存／网络发送，业务层不逐次调用 flush。

| 平台 | 自动事件／能力 | 常见预置信息与本工程状态 |
| --- | --- | --- |
| Firebase Analytics | first_open、session_start、user_engagement、app_update、os_update、screen_view | 采集开关开启；版本、设备／系统和会话信息由 SDK 添加。screen_view 主要反映 Activity，本工程 Compose 路由另发 f_page_view |
| Firebase 购买／崩溃／推送 | in_app_purchase；Crashlytics 联动 app_exception；FCM notification_* 为条件触发 | Play 自动购买受 SDK、商店及平台配置影响；测试／沙盒可能被过滤。Crashlytics／Messaging 各有独立开关，不把无对应操作的事件当作必然存在 |
| AppsFlyer | 安装归因、会话／应用打开（SDK 文档中的 af_app_opened） | start 后 SDK 自动管理安装与会话；设备、系统、版本、AppsFlyer ID、可用的广告标识和投放信息由 SDK 管理。当前未覆盖 SDK 默认会话间隔；业务 a_app_launch 与 SDK 会话不可相加 |
| 数数 | ta_app_start、ta_app_end、ta_app_install、ta_app_view、ta_app_click、ta_app_crash | 代码请求开启这六类，并调用 Fragment 页面跟踪。预置参数如 #resume_from_background、#duration（秒）、#screen_name、#title、元素信息、崩溃原因 |

数数工程当前没有接入自动采集 Gradle 插件，且主界面是 Compose；因此不能承诺 ta_app_click 和 Fragment 自动浏览全面生效，业务统计使用 s_tab_click、s_page_view 等明确调用。SDK 自动时长的单位／会话边界可能与本文件的毫秒口径不同。数数第三方共享只在 AppsFlyer 开启时启用，用于平台身份关联，不是额外的业务事件。

当前 dev/prod 的 ENABLE_FIREBASE_ANALYTICS、ENABLE_APPSFLYER、ENABLE_THINKINGDATA 均为 true；数数 TD_DEBUG_MODE=false。本次不修改平台身份、自动采集开关或事件后台配置。

官方依据（2026-09-16 核对）：[Firebase 自动事件](https://support.google.com/analytics/answer/9234069?hl=en)、[AppsFlyer Android 初始化与会话](https://dev.appsflyer.com/hc/docs/integrate-android-sdk)、[AppsFlyer 应用内事件及收入参数](https://dev.appsflyer.com/hc/docs/in-app-events-android)、[数数 Android 自动采集](https://doc.thinkingdata.cn/tdamanual_dev/installation/installation_menu/client_sdk/android_sdk_installation/android_sdk_autotrack.html)。

## 7. 归因上报与保留事件

登录请求的 attribution 与 `POST attribution/report` 是业务接口上报，不是手动分析事件，不加平台前缀。保留设备、包名、版本、投放来源／活动／广告组／素材、用户、原始 extra_data 的真实类型；SDK 归因失败不伪造 Organic。晚到有效回调独立补报。正常缓存读取最多额外等待 ATTRIBUTION_CACHE_WAIT_MS（当前 200ms），避免登录抢在缓存加载前丢失历史参数；磁盘卡住不无限阻塞登录。

| 事件 | 状态 | 后续说明 |
| --- | --- | --- |
| `save_video` | 暂时没有此功能，后期开发 | 当前无保存到相册入口，不发送伪造点击／结果；以后实现时需区分点击、权限／保存结果并补资源 ID 与模板 ID |

## 8. 自有后端 events/report

- 参照当前 `android_joly/core/.../network/api/EventApi.kt`、`ReportEventRequest`、`BackendAnalyticsSink` 和 `AnalyticsRoutingPolicy` 的接口结构，按用户最新要求统一四端分发并为后端添加 z_ 前缀（与参考项目原无前缀规则不同）；由 Core 持有接口、序列化模型、异步队列及 Hilt 网络绑定；app 分发层只负责把已有业务事件交给出口。
- `POST events/report` 拼接当前 flavor 的业务 API，实际为 `/api/v1/events/report`；dev 使用 test.appjoly.com，prod 使用 release.zorv.date。使用 publicClient 和公共客户端请求头，登录前也可上报，不触发认证刷新。
- 请求字段：`device_id`、加 `z_` 前缀的 `event_type`、触发时毫秒 `event_time`、可空 `user_id`、实际 `package_name`／`app_version`、`platform=android`、`parameters: Map<String,String>`。设备 ID 独立从 SessionStorage 读取；账号、时间和参数在入队时冻结，不在发送时改挂新用户。SDK 标量规范之后按契约将参数值转字符串，一般布尔为字符串 `1`／`0`，支付 af_success 保留字符串 true／false，沿用统一业务参数中的 af_revenue／af_currency 等官方字段，不单独生成第二笔收入。
- 配置 `config/app.properties` 的 `ENABLE_BACKEND_ANALYTICS=true`，可由 dev/prod 独立覆盖；与三个 SDK 开关独立。所有业务事件进入四端，已移除 EventAudience 及专属分发分支，历史投放和第三方支付页面事件也进入后端。
- 使用独立 IO 协程和有界内存队列（复用 ANALYTICS_QUEUE_CAPACITY，当前 256）；队列满丢弃新事件。HTTP 非成功、空响应、业务 code 非 0、网络／解析异常均隔离，后续事件继续处理；协程取消正常传播。无应用层重试、持久化补偿或可靠交付承诺，不阻塞 SDK 分发及业务流程。
- Core 的 consumer rules 精确保留 EventApi 动态代理入口、方法与反射元数据，序列化使用 Kotlin 生成的 serializer 和库自带规则，不关闭 release 混淆。
- 此接口是行为埋点，不是模板内容举报接口。当前模板 Report 仍为本地交互及用户确认的提示文案，不能以本次接入声明举报已被后台受理。

## 9. 实现、可靠性与验收

- Core `EventTracker` 定义业务契约、标量规范与支付口径；app `BusinessEventQueue` 捕获触发时账号／模式／会话，`AnalyticsHub` 按平台分发。SDK 与后端上报异常被隔离，不影响认证、生成和支付。
- 手动事件内存队列上限 256；进程被杀、队列满或 SDK 初始化／网络失败可能丢失事件，不宣称可靠交付。终态去重记录保存最近 10000 个键，超出窗口／清除数据后可能重新上报；键按账号隔离，不存凭据。SDK 交付不是 exactly-once，应结合 event_id、af_order_id／task_id 在数仓去重。
- app 分发前发现账号已切换时丢弃旧账号事件；已进入后端队列的事件保留原 user_id 请求字段，不改挂新账号。登录前事件保留空 user_id。Debug 设计预览默认 NoOp，不把 fixture 当成真实用户操作。
- Analytics／BackendAnalytics 标签仅输出事件名、字段名及错误类别；通用 HTTP 日志仍遵循现有 Debug 与 ENABLE_DEBUG_LOG、HTTP_LOG_REDACTION 配置，dev Debug 可能输出请求正文，release 不输出。
- 核验内容包含新旧名称、公共参数类型、收入仅主事件、第三方 paid 未 fulfilled、关闭／超时非失败、任务终态重复查询、归因缓存竞态及缓存卡住。
- 具体构建、测试和设备证据见 埋点验证记录（历史参考，契约以本文正文和随包源码为准）。自有后端及三个平台后台实收、真实付费交易、各设备自动采集覆盖尚需对应环境联调。

## 参考文档的业务定义（待确认采用范围）

参考方案是后台授权的录播编排，各设备独立播放，不是摄像头推流或连麦。

参考完整范围包括：首页直播卡、Live 导航与人物目录、公开房及评论、片段编排、普通礼物、私密报价与确认、按规则计费与动作、充值、结束与对账、My 历史与回放及消费流水。

### 用户确认的计费规则

- 采用预扣费：首次进入私密房一次性扣除 3 分钟费用。
- 首次 3 分钟结束后，每个后续分钟的第一秒扣除该 1 分钟费用。
- 展示价格由后台提供；费用扣除及有效观看期限以后台结果为准，客户端不增加本地定时扣币或自行宣告续费成功。
- `quote.minute_price`、`initial_minutes`、`time_cost`、`total` 等必须与上述产品政策对齐。后台若返回非 3 分钟，不擅自改响应或按本地 3 倍单价构造收费请求，应作为契约差异处理。

### 覆盖参考文档的流程与实现约束

- 用户本轮明确授权的“私密 Start → 不足充值 → 成功自动入房”覆盖参考文档“取消等待意图后充值、充值后重新确认”的产品流程。普通礼物充值仍不自动补送。
- 自动续接仅适用于本次用户已点击 Start 的原主播/visit、当前账号会话及仍有效的页面意图，并核实原充值订单实际到账；离房、关闭流程或切账号后，不迟到自动进入。
- 优先核实原入场 intent：若已 completed，复用原 session；若 waiting_funds，按后台明确支持的恢复协议继续。不得无条件创建第二个 intent、换幂等键重复扣费，亦不得凭支付客户端成功回调伪造余额到账或开房成功。
- 参考已提供 resume 接口，但约定仅手动 Retry；需要后台确认其支持本次充值成功后的自动续接，以及原 quote/intent 过期、变价和已自动完成的处理。原冻结报价不能被静默替换为用户未确认的新价格。
- 缓冲页可并行完成真实入场确认和媒体准备；2–4 秒是用户期望的正常体验，不能仅因计时结束播放未授权媒体。实际网络慢/媒体失败时的等待、重试与退出反馈需明确，不能承诺网络未就绪也必定 4 秒入房。
- 用户确认：计费由后台考虑。首次计费起点、缓冲期间如何计费、扣费与续费边界由后台实现并给出权威结果，客户端不另定规则、不本地扣款、不自行延后或延长计费/观看期限。客户端展示真实报价，按后台场次状态与 `paid_until` 等授权处理播放，按契约提交真实播放事实；不再将计时起点作为需要用户选择的产品问题。首次 3 分钟及后续逐分钟预扣仍作为已确认产品要求交由后台落实，联调核对实际返回。
- 私密结束、余额不足续费、缓冲关闭及后台/锁屏的停费收口继续讨论；关闭 UI 不能冒充后台场次已结束。

### 实施边界与建议

- 结束/离页保留原 session 对账及真实播放事实；结束缓冲不重新开房或自动续费，不由本地计时触发新扣款。
- 动作受理、媒体准备和真实播放分别处理；仅 HTTP accepted 不直接显示已播放。具体 Sent 反馈及是否自动收起列表随动作流程进一步确认。
- 私密项目不足充值后是否自动重送/重试该动作尚未确认；本轮仅确认打开充值弹窗，不沿用“入场充值后自动进入”去推导自动赠礼。

### 关闭确认框与返回行为（补充确认）

- 设计说明 `You'll still be charged for the full 3 minutes.` 表达首次 3 分钟起步的收费提示，最终费用、续费和退款仍由后台负责；不据该文案将超过 3 分钟的场次总费用错误展示为固定 3 分钟。

# zorv Android 打包机打包操作文档

本文档用于在专用 Windows 打包机上构建 zorv Android 包，适合作为后续发版、内部测试、Google Play 上传前的操作参考。

> 说明：文档中的密码、证书、确认文件属于本地敏感配置，不应提交到 Git。

## 1. 打包机环境要求

打包机建议固定使用以下环境：

- Windows PowerShell
- Git
- JDK 17
  - 当前打包机示例路径：`C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot`
- Android SDK
  - 当前打包机示例路径：`C:\Android\Sdk`
- Android SDK 包：
  - `cmdline-tools;latest`
  - `platform-tools`
  - `platforms/android-37.0`
  - `build-tools/36.0.0`

检查环境变量：

```powershell
$env:JAVA_HOME
$env:ANDROID_SDK_ROOT
git --version
java -version
adb version
```

如果需要安装 Android SDK 组件：

```powershell
android --sdk="$env:ANDROID_SDK_ROOT" sdk install platforms/android-37.0 build-tools/36.0.0 platform-tools
```

注意：这里使用的是 Android CLI 的包名 `platforms/android-37.0`。不要使用 `sdkmanager "platforms;android-37"`，这个包名在当前打包机上会提示找不到。

## 2. 拉取最新代码

首次在打包机上拉取仓库：

```powershell
cd C:\Users\Administrator\Desktop
git clone git@github.com:klgz-wl/echatApp.git zorv_android
cd .\zorv_android
```

后续每次打包前更新代码：

```powershell
cd C:\Users\Administrator\Desktop\zorv_android
git status --short
git checkout main
git pull --ff-only origin main
git log -1 --oneline
```

如果是第一次连接 GitHub SSH，会提示是否信任 GitHub 主机，输入 `yes` 即可。若出现 `Permission denied (publickey)`，说明打包机的 GitHub SSH Key 还没有配置好，需要先配置 SSH Key。

## 3. 准备本地签名与正式发布确认文件

正式 prod 包需要以下本地文件：

```text
config/project-upload.jks
config/signing-release.local.properties
config/prod-confirmation.local.properties
.core-scaffold/platform-evidence.json
local.properties
```

这些文件不要提交到 Git，原因如下：

- `config/project-upload.jks`：正式上传证书，属于敏感私钥文件。
- `config/signing-release.local.properties`：包含 keystore 密码和 key 密码。
- `config/prod-confirmation.local.properties`：正式发布人工确认清单，可能包含本地确认信息。
- `.core-scaffold/platform-evidence.json`：正式平台验收证据，本地生成。
- `local.properties`：本机 Android SDK 路径，不同机器不同。

### 3.1 传输 keystore 到打包机

如果已经有可用的 `config/project-upload.jks`，不要重新生成，直接安全传输到打包机项目目录：

```text
C:\Users\Administrator\Desktop\zorv_android\config\project-upload.jks
```

可选方式：

- RDP / 云服务器控制台文件上传。
- SFTP / SCP。
- 临时加密压缩包传输后在打包机解压。

不要通过 Git 提交 keystore。

### 3.2 配置签名文件

在打包机项目根目录创建或编辑：

```powershell
notepad config\signing-release.local.properties
```

内容格式：

```properties
storeFile=config/project-upload.jks
storePassword=你的keystore密码
keyAlias=zorv-upload
keyPassword=你的key密码
```

当前项目使用的正式上传证书 alias 为：

```text
zorv-upload
```

可以用下面命令验证证书是否可读：

```powershell
keytool -list -v -keystore config\project-upload.jks -alias zorv-upload
```

如果能看到证书详情，说明 keystore、alias、密码可用。

### 3.3 配置正式发布确认文件

从模板复制：

```powershell
Copy-Item config\prod-confirmation.properties.example config\prod-confirmation.local.properties
notepad config\prod-confirmation.local.properties
```

至少确认：

```properties
confirmed=true
applicationId=com.zorv.app
app.display.name=zorv
build.string.PAYMENT_FLOW=SERVICE
build.string.PRIVACY_POLICY_URL=https://sites.google.com/view/zorvprivacy/home
build.string.TERMS_OF_SERVICE_URL=https://sites.google.com/view/zorvterms/home
```

正式 prod 当前关键配置：

- 包名：`com.zorv.app`
- App 名称：`zorv`
- API / 支付 / WebSocket 域名：`release.zorv.date`
- 图片、视频等媒体 CDN：`cdn.zorv.date`
- 支付流程：`SERVICE`
- 隐私政策：`https://sites.google.com/view/zorvprivacy/home`
- 服务条款：`https://sites.google.com/view/zorvterms/home`

## 4. 正式打包前校验

建议每次打正式包前先执行校验：

```powershell
.\gradlew.bat `
  "-PgoogleMavenMirror=https://maven.aliyun.com/repository/google" `
  "-PmavenCentralMirror=https://maven.aliyun.com/repository/central" `
  "-PgradlePluginPortalMirror=https://maven.aliyun.com/repository/gradle-plugin" `
  :app:verifyFormalRelease `
  :app:verifyProdReleaseRuntimeConfig `
  :app:validateSigningProdRelease `
  --no-parallel `
  --max-workers=1 `
  --no-configuration-cache `
  --console=plain
```

说明：

- `verifyFormalRelease`：检查正式包名、正式签名、确认文件，避免误用 dev/sharedDev 证书。
- `verifyProdReleaseRuntimeConfig`：检查 prod 运行时配置，例如包名、版本、后端域名、CDN 域名、支付模式、地区屏蔽等。
- `validateSigningProdRelease`：检查 prod release 签名配置是否完整。

不建议把 `:app:signingReport` 放进正式校验流水里。之前在打包机上它可能因 Gradle provider 值未就绪而失败，但不代表正式签名不可用。签名证书建议使用 `keytool` 或 `apksigner` 验证。

## 5. 构建 Google Play AAB 包

上传 Google Play 使用 AAB：

```powershell
.\gradlew.bat `
  "-PgoogleMavenMirror=https://maven.aliyun.com/repository/google" `
  "-PmavenCentralMirror=https://maven.aliyun.com/repository/central" `
  "-PgradlePluginPortalMirror=https://maven.aliyun.com/repository/gradle-plugin" `
  :app:bundleProdRelease `
  --no-parallel `
  --max-workers=1 `
  --no-configuration-cache `
  --console=plain
```

输出文件：

```text
app\build\outputs\bundle\prodRelease\app-prod-release.aab
```

可选：复制到交付目录并重命名。手动修改 AAB 文件名不影响包内部信息。

```powershell
New-Item -ItemType Directory -Force .\dist
Copy-Item app\build\outputs\bundle\prodRelease\app-prod-release.aab .\dist\zorv-prod-1.0.1.aab
```

## 8. 打包后验证

### 8.1 查看产物时间

确认产物是刚刚生成的：

```powershell
Get-Item app\build\outputs\bundle\prodRelease\app-prod-release.aab
Get-Item app\build\outputs\apk\prod\release\app-prod-release.apk
```

如果担心拿到旧包，可以先删除旧产物再打包：

```powershell
Remove-Item app\build\outputs\bundle\prodRelease\app-prod-release.aab -Force -ErrorAction SilentlyContinue
Remove-Item app\build\outputs\apk\prod\release\app-prod-release.apk -Force -ErrorAction SilentlyContinue
```

### 8.2 验证 APK 签名

```powershell
& "$env:ANDROID_SDK_ROOT\build-tools\36.0.0\apksigner.bat" verify --print-certs app\build\outputs\apk\prod\release\app-prod-release.apk
```

### 8.3 查看 AAB 签名证书

```powershell
keytool -printcert -jarfile app\build\outputs\bundle\prodRelease\app-prod-release.aab
```

### 8.4 生成文件 hash

hash 不是首次上传 Google Play 的强制要求，但用于交付核对很有价值：测试、运营或发布人员可以确认大家拿到的是同一个文件。

```powershell
Get-FileHash app\build\outputs\bundle\prodRelease\app-prod-release.aab -Algorithm SHA256
Get-FileHash app\build\outputs\apk\prod\release\app-prod-release.apk -Algorithm SHA256
```

## 9. 常见问题

### 9.1 Gradle 依赖或插件下载失败

如果报错类似找不到：

- `com.google.gms.google-services`
- `com.android.application`
- `com.android.tools.build:gradle`

优先使用带阿里云镜像参数的命令，也就是本文档中的 `-PgoogleMavenMirror`、`-PmavenCentralMirror`、`-PgradlePluginPortalMirror`。

### 9.2 构建看起来卡住

release 包在 R8、资源处理、依赖下载阶段可能长时间无输出。可以开一个新的 PowerShell 看 Java 进程是否还在工作：

```powershell
Get-Process java |
  Select-Object Id,CPU,@{Name="RAM_MB";Expression={[math]::Round($_.WorkingSet64 / 1MB)}},StartTime
```

如果 CPU 时间还在增长、内存占用正常，通常继续等待即可。之前打包机上完整 prod AAB 构建约数分钟，但首次构建或缓存失效时会更久。

### 9.3 输出目录里显示昨天的包

Gradle 正常会覆盖同名产物。判断是否最新主要看 `Date modified`。

如果要避免误拿旧包，可以先删除旧产物，再重新执行构建命令：

```powershell
Remove-Item app\build\outputs\apk\prod\release\app-prod-release.apk -Force -ErrorAction SilentlyContinue
Remove-Item app\build\outputs\bundle\prodRelease\app-prod-release.aab -Force -ErrorAction SilentlyContinue
```

### 9.4 `signingReport` 失败

之前打包机上执行 `:app:signingReport` 可能出现：

```text
Cannot query the value of this provider because it has no value available.
```

这不一定代表正式签名不能用。正式发包应以以下方式确认：

- `keytool -list -v -keystore config\project-upload.jks -alias zorv-upload`
- `:app:validateSigningProdRelease`
- APK 产物用 `apksigner verify --print-certs`

### 9.5 正式包校验失败：缺少 `.core-scaffold/platform-evidence.json`

`bundleProdRelease` 和 `assembleProdRelease` 会依赖 `verifyCoreFullChainEvidence`。如果缺少真实平台验收文件，会阻止正式包生成。

这是发布保护的一部分，不建议随意用 `-x :app:verifyCoreFullChainEvidence` 跳过。只有在明确只是临时本地构建、且负责人确认风险时，才考虑临时跳过。

## Subtitle readiness and synchronization

- Media3 text rendering does not block video while an external VTT loads. Prepare and parse the selected subtitle into bounded RAM before resuming its video, using an unauthenticated media data source (JWT remains resolver-only), cancellable IO, timeout and an 8MiB limit; never persist signed subtitle URLs/bytes. Keep the active video paused during selected-caption preparation, retain user pause intent, and surface retry/off on failure without invalidating the video grant.
- Keep one player for the same episode/authorization/video URL/replay. Parse original VTT with Media3 WebvttParser into native CuesWithTiming and render the matching intervals against that player’s currentPosition (50ms refresh). Do not attach external subtitle media or rebuild video sources on track changes; this avoids delayed text extraction and paused-seek races. Never restart video or replay an old seek command during a track change. Apply seek once per command serial, clear old caption cues immediately on selection changes, and discard late loading results by track/media ownership.
- Debug synchronization evidence contains only elapsed duration, video position/duration, cue presentation time/count, and VTT first/last cue times. Never alter VTT timestamps to hide mismatched source assets; if subtitle cue times are outside the video duration, report the asset mismatch separately. Verify timed cues at known positions, delayed subtitle preparation holding video, same-URL language changes, subtitle-off clearing, end-of-playback caption clearing and no extra play/unlock requests.

- User policy supersedes the former Off choice: subtitle menus list only actual server tracks, with the first returned track selected and resolved by default for a new grant/episode. Preserve a valid explicit language across grant refreshes; choose the first if that language disappears. Empty tracks show an unavailable state, never a fabricated Off option.
